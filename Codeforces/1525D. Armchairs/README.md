## 문제 설명

$n$개의 팔걸이의자가 왼쪽에서 오른쪽으로 $1$번부터 $n$번까지 번호가 매겨져 있습니다. 일부 의자에는 사람이 앉아 있고(의자 하나에 최대 한 명), 나머지는 비어 있습니다. 사람이 앉아 있는 의자의 개수는 $\frac{n}{2}$보다 크지 않습니다. 어떤 이유로, 당신은 사람들에게 자신의 의자에서 다른 의자로 옮기도록 지시하고 싶습니다. $i$번째 의자에 누군가 앉아 있고 $j$번째 의자가 비어 있다면, $i$번째 의자에 앉아 있는 사람에게 $j$번째 의자로 옮기라고 지시할 수 있습니다. $i$번째 의자에서 $j$번째 의자로 옮기는 데 걸리는 시간은 $|i - j|$분입니다. 이 작업은 몇 번이든 수행할 수 있지만, 작업은 순차적으로 이루어져야 합니다. 즉, 마지막으로 지시한 사람이 목적지 의자로 이동을 끝내기 전까지는 다른 사람에게 이동을 지시할 수 없습니다. 당신이 원하는 상황은 다음과 같습니다: 처음에 사람이 앉아 있던 모든 자리는 비어 있어야 합니다. 이를 달성하는 데 필요한 최소 시간은 얼마일까요?

## 입력

첫 번째 줄에는 정수 $n$ ($2 \le n \le 5000$) — 안락의자의 개수가 주어진다. 두 번째 줄에는 $n$개의 정수 $a_1, a_2, \dots, a_n$ ($0 \le a_i \le 1$)이 주어진다. $a_i = 1$이면 $i$번째 안락의자가 처음에 사용 중이라는 뜻이고, $a_i = 0$이면 처음에 비어 있다는 뜻이다. 사용 중인 안락의자의 개수는 최대 $\frac{n}{2}$개이다.

## 출력

처음에 사람이 앉아 있던 모든 좌석이 비게 되는 상황을 만들기 위해 필요한 최소 소요 시간(분)을 정수 하나로 출력하세요.

## 코드 리뷰

- 효율성: 보통
- 시간복잡도: 시간복잡도 O(C×NC) (최악의 경우 O(N²/4), N=5000이면 약 6,250,000회 연산) / 공간복잡도 O(C×NC)로 2차원 DP 테이블을 전부 저장
- 더 나은 알고리즘: 이 문제의 표준 해법 자체가 O(N²) DP이므로 시간복잡도 측면에서는 적절합니다. 다만 현재 dp[i][j]는 dp[i-1][*]과 dp[i][*] 두 행만 참조하므로 2차원 배열 전체를 유지할 필요가 없습니다. 1차원 배열(길이 nc)을 재사용하면서 i를 증가시키는 방식(롤링 배열)으로 공간을 O(NC)로 줄일 수 있습니다. 예: prev = dp[i-1] 행만 보관하고 cur를 새로 계산하는 식으로 바꾸면 메모리 사용량이 크게 줄어듭니다. 참고로 그래프 매칭/MCMF로도 풀리지만 N≤5000에서는 DP가 더 간단하고 빠릅니다.

### 잘한 점

- occupied-free 매칭이 순서를 보존해야 최적이라는 핵심 성질을 올바르게 이용해 DP 전이식을 구성함
- i<=j 범위로 루프를 제한하여 불필요한 계산을 줄이는 최적화를 적용함
- occupied 개수가 0인 엣지 케이스를 미리 처리하여 예외 상황을 방지함

### 개선할 점

- 2차원 DP 테이블을 전부 메모리에 올려 O(C×NC)의 공간을 사용하는데, 실제로는 이전 행만 필요하므로 1차원 배열로 최적화할 수 있음
- 순수 파이썬 중첩 for 루프로 최악의 경우 625만 회 반복을 수행해, 입력 크기가 커질 경우 시간 제한에 여유가 적을 수 있음 (PyPy 사용이나 numpy 벡터화 고려 필요)
- dp 배열 초기화(dp[0][i] 계산) 로직이 별도의 반복문으로 분리되어 있어 전체 DP 전이와 다소 일관성이 떨어짐

### 상세 피드백

문제의 핵심 아이디어(occupied와 free 위치를 순서를 보존한 채로 매칭해야 최소 비용이 된다는 사실)를 정확히 파악하고, i<=j 조건으로 불필요한 계산을 줄인 점이 좋습니다. dp[i][j] = min(dp[i-1][j-1]+cost, dp[i][j-1]) 전이식도 올바르게 구현되어 정답을 도출합니다. 다만 2차원 리스트를 통째로 생성하기 때문에 C와 NC가 모두 n/2에 가까운 최악의 경우(N=5000) 약 625만 개의 셀을 담는 리스트의 리스트를 만들게 되어 메모리 사용량이 불필요하게 큽니다. 파이썬 리스트의 객체 오버헤드까지 고려하면 512MB 제한에 근접하거나 넘을 위험이 있고, 순수 파이썬 이중 루프 자체도 시간 제한(2초)에 비해 여유가 크지 않습니다. dp 배열을 1차원으로 롤링하거나 PyPy 제출, 혹은 numpy 벡터화를 활용하면 안정성이 크게 개선됩니다. 전체적으로 알고리즘 설계는 정확하지만 구현 최적화(공간/시간) 여지가 남아있는 풀이입니다.
