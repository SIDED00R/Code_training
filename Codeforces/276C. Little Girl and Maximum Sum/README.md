## 문제 설명

어린 소녀는 배열 쿼리와 관련된 문제를 매우 좋아합니다. 어느 날 그녀는 꽤 잘 알려진 문제를 마주쳤습니다. 길이가 $n$인 배열이 주어지고 (배열의 원소는 $1$부터 시작하여 인덱스가 매겨짐), 쌍으로 이루어진 $q$개의 쿼리 $l_i, r_i$ ($1 \le l_i \le r_i \le n$)가 주어집니다. 여러분은 각 쿼리마다 인덱스 $l_i$부터 $r_i$까지 (양 끝점 포함) 배열 원소들의 합을 구해야 합니다. 어린 소녀는 이 문제가 꽤 지루하다고 느꼈습니다. 그녀는 쿼리에 답하기 전에 쿼리 답들의 총합이 가능한 최대가 되도록 배열의 원소들을 재배치하기로 결합했습니다. 여러분의 임무는 이 최대 합의 값을 찾는 것입니다.

## 입력

첫 번째 줄에는 배열의 원소 개수와 쿼리의 개수를 나타내는 두 정수 $n$ ($1 \le n \le 2\cdot10^5$)과 $q$ ($1 \le q \le 2\cdot10^5$)가 공백으로 구분되어 주어집니다. 다음 줄에는 배열의 원소들을 나타내는 $n$개의 정수 $a_i$ ($1 \le a_i \le 2\cdot10^5$)가 공백으로 구분되어 주어집니다. 이어지는 $q$개의 각 줄에는 $i$번째 쿼리를 나타내는 두 정수 $l_i$와 $r_i$ ($1 \le l_i \le r_i \le n$)가 공백으로 구분되어 주어집니다.

## 출력

단 한 줄에 정수 하나를 출력한다 — 배열의 원소들을 재정렬한 후 쿼리 답들의 최댓값이다. C++에서 64비트 정수를 읽거나 쓸 때 `%lld` 지정자를 사용하지 말아 주세요. `cin`, `cout` 스트림이나 `%I64d` 지정자를 사용하는 것을 권장합니다.

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: O(N log N + Q)

### 잘한 점

- 차분 배열(Difference Array)과 누적 합을 활용해 구간 쿼리의 빈도수를 O(N + Q)에 구함
- 가장 많이 조회되는 인덱스에 가장 큰 값을 매칭하는 그리디 전략을 올바르게 적용함
- 대용량 입력에 대해 효율적인 리스트 연산을 사용함

### 개선할 점

- 변수명 stack이 실제로는 스택 구조가 아닌 빈도수와 누적합을 담는 리스트로 사용되어 혼동을 줄 수 있음
- p_sum 배열의 크기를 n+2로 잡고 슬라이싱(stack[:-1])을 처리하는 방식이 약간 복잡함

### 상세 피드백

제출된 코드는 이 문제를 해결하기 위한 최적의 접근법을 훌륭하게 구현했습니다. 각 구간 쿼리에 대해 일일이 값을 더하는 대신, 차분 배열(Difference Array) 기법과 누적 합(Prefix Sum)을 사용하여 각 인덱스가 쿼리에 포함되는 빈도수를 O(N + Q) 시간에 정확히 계산했습니다. 그 후, 빈도가 높은 인덱스 위치에 배열의 큰 값들을 배치하는 그리디(Greedy) 알고리즘 전략을 적용하여 전체 복잡도 O(N log N)으로 효율적으로 문제를 해결했습니다. 변수명이 약간 직관적이지 않은 부분(예: stack이라는 이름으로 빈도수 배열을 관리한 점)이 있으나, 전체적인 논리와 파이썬의 리스트 슬라이싱 및 정렬을 활용한 구현력은 매우 훌륭합니다. N과 Q가 최대 2x10^5까지 주어지므로 파이썬에서 입출력 속도에 주의해야 할 수도 있으나 알고리즘 자체는 타임아웃 없이 통과하기에 충분히 빠릅니다.
