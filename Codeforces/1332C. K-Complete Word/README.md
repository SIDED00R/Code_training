## 문제 설명

길이가 $n$인 단어 $s$가 다음 조건을 만족하면 $k$-완전하다고 부릅니다.

모든 $1 \le i \le n$에 대해 $s_i=s_{n+1-i}$를 만족하는, 즉 $s$가 팰린드롬이다.
모든 $1 \le i \le n-k$에 대해 $s_i=s_{k+i}$를 만족하는, 즉 $s$가 주기 $k$를 가진다.

예를 들어, " abaaba "는 $3$-완전한 단어이지만, " abccba "는 그렇지 않습니다.

Bob에게 소문자 라틴 문자로만 이루어진 길이 $n$의 단어 $s$와 정수 $k$가 주어지며, $n$은 $k$로 나누어집니다. 그는 $s$를 어떤 $k$-완전한 단어로든 변환하고 싶어 합니다. 이를 위해 Bob은 어떤 $i$ ($1 \le i \le n$)를 선택하여 위치 $i$에 있는 문자를 다른 소문자 라틴 문자로 바꿀 수 있습니다.

이제 Bob은 $s$를 어떤 $k$-완전한 단어로 변환하기 위해 바꿔야 하는 최소 문자 개수를 알고 싶어 합니다. 만약 단어 $s$가 이미 $k$-완전하다면 Bob은 아무것도 바꾸지 않아도 됩니다.

$t$개의 테스트 케이스에 대해 각각 독립적으로 답을 구해야 합니다.

## 입력

첫 번째 줄에는 정수 $t$ ($1 \le t\le 10^5$)가 주어지며, 이는 테스트 케이스의 개수입니다. 각 테스트 케이스의 첫 번째 줄에는 두 정수 $n$과 $k$ ($1 \le k \lt n \le 2 \cdot 10^5$, $n$은 $k$로 나누어집니다)가 주어집니다. 각 테스트 케이스의 두 번째 줄에는 길이 $n$인 단어 $s$가 주어집니다. 단어 $s$는 소문자 라틴 문자로만 이루어져 있음이 보장됩니다. 그리고 모든 테스트 케이스에 대한 $n$의 합은 $2 \cdot 10^5$를 초과하지 않음이 보장됩니다.

## 출력

각 테스트 케이스에 대해, $s$를 어떤 $k$-완전 단어로 변환하기 위해 바꿔야 하는 문자의 최소 개수를 나타내는 정수 하나를 출력한다.

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: O(n) per테스트케이스 (전체 합산 시 O(sum n) = O(2×10^5)), 알파벳 상수(26)를 곱해도 선형

### 잘한 점

- 팔린드롬+주기 조건을 동치 클래스(대칭 위치 쌍)로 묶어 빈도 계산 후 최소 교체 횟수를 구하는 핵심 아이디어를 정확히 구현함
- k가 짝수/홀수인 경우를 분리해서 중앙 문자 처리까지 빠짐없이 커버함
- 전체 시간복잡도가 O(n)으로 최적에 가까운 효율적인 풀이

### 개선할 점

- t가 최대 1e5인데 매 테스트케이스마다 input()을 두 번 호출하는 방식은 CPython에서 I/O 오버헤드로 TLE 위험이 있음 (sys.stdin.readline이나 전체 입력을 한번에 읽는 방식이 더 안전)
- dic, now_word, idx 같은 변수명이 다소 불명확하여 가독성이 떨어짐 (예: letter_count, block, offset 등으로 개선 가능)
- split_word 리스트를 미리 만들지 않고 word 문자열에서 바로 인덱싱해도 되는데 불필요하게 O(n) 추가 메모리를 사용함

### 상세 피드백

이 문제의 핵심 아이디어는 각 블록(길이 k) 내에서 팔린드롬 대칭 위치(i와 k-1-i)들을 전체 블록에 대해 하나의 동치 클래스로 묶고, 그 클래스에서 가장 빈도가 높은 문자를 기준으로 나머지를 바꾸는 것(= 클래스 크기 - 최대빈도)인데, 제출 코드는 이를 정확히 구현했습니다. idx를 0부터 k//2-1까지 순회하며 front/back 문자를 defaultdict로 집계하고, k가 홀수일 때 중앙 문자를 별도로 처리하는 로직도 올바릅니다. 전체 연산량이 각 idx마다 n/k개 블록을 순회하므로 (k//2)*(n/k) ≈ n/2로 선형이며, DSU로 그룹을 만드는 에디토리얼 방식과 본질적으로 동일한 효율을 보입니다. 다만 t가 최대 1e5까지 주어지는데 input()을 매 테스트케이스마다 두 번씩(라인 단위) 호출하는 방식은 CPython에서 호출 오버헤드가 누적되어 시간 제한(2초)에 걸릴 위험이 있습니다. sys.stdin을 통째로 읽어 split하거나 sys.stdin.readline을 사용하는 것이 안전합니다. 또한 word가 문자열이라 word[-idx-1]과 같은 슬라이싱이 매번 새로운 객체를 만들지는 않지만, split_word를 리스트로 미리 슬라이싱해두는 부분에서 메모리 사용량이 O(n)만큼 추가로 발생하는 점도 참고할 만합니다. 알고리즘적으로는 더 개선할 부분이 거의 없는 최적해에 가깝고, I/O 최적화 정도만 보완하면 완성도가 높습니다.
