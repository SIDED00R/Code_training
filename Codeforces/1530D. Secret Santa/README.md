## 문제 설명

매년 12월, VK는 직원들을 위해 "시크릿 산타"라는 이름의 행사를 전통적으로 개최합니다. 진행 방식은 다음과 같습니다. $1$부터 $n$까지 번호가 매겨진 $n$명의 직원이 행사에 참가합니다. 각 직원 $i$에게는 서로 다른 직원 $b_i$가 배정되며, 직원 $i$는 그 직원에게 새해 선물을 해야 합니다. 각 직원은 정확히 한 명의 다른 직원에게 배정되며, 누구도 자기 자신에게 배정되지 않습니다 (단, 두 직원이 서로에게 배정될 수는 있습니다). 형식적으로 말하면, 모든 $b_i$는 $1$부터 $n$ 사이의 서로 다른 정수여야 하며, 어떤 $i$에 대해서도 $b_i \ne i$가 성립해야 합니다. 이 배정은 보통 무작위로 생성됩니다. 올해는 실험적으로, 모든 행사 참가자들에게 누구에게 선물을 하고 싶은지 물어보았습니다. 각 직원 $i$는 직원 $a_i$에게 선물을 하고 싶다고 말했습니다. 직원들의 바람이 최대한 많이 충족되도록 유효한 배정 $b$를 찾으세요.

## 입력

각 테스트는 여러 개의 테스트 케이스를 포함합니다. 첫 번째 줄에는 테스트 케이스의 개수 $t$ ($1 \le t \le 10^5$)가 주어집니다. 이어서 각 테스트 케이스에 대한 설명이 주어집니다.

각 테스트 케이스는 두 줄로 구성됩니다. 첫 번째 줄에는 행사 참가자의 수를 나타내는 정수 $n$ ($2 \le n \le 2 \cdot 10^5$)이 주어집니다. 두 번째 줄에는 $1$번부터 $n$번까지 순서대로 직원들의 희망 사항을 나타내는 $n$개의 정수 $a_1, a_2, \ldots, a_n$ ($1 \le a_i \le n$; $a_i \ne i$)이 주어집니다.

모든 테스트 케이스에 대한 $n$의 합은 $2 \cdot 10^5$를 넘지 않음이 보장됩니다.

## 출력

각 테스트 케이스에 대해 두 줄을 출력하세요. 첫 번째 줄에는 정수 $k$ ($0 \le k \le n$) 하나를 출력하세요 — 이는 당신의 배정에서 충족된 소원의 개수입니다. 두 번째 줄에는 $n$개의 서로 다른 정수 $b_1, b_2, \ldots, b_n$ ($1 \le b_i \le n$; $b_i \ne i$)을 출력하세요 — 이는 직원 $1, 2, \ldots, n$에게 배정된 직원들의 번호입니다. $k$는 $a_i = b_i$를 만족하는 $i$의 개수와 같아야 하며, 가능한 한 커야 합니다. 답이 여러 개 존재한다면, 그중 하나를 출력하세요.

## 코드 리뷰

- 효율성: 보통
- 시간복잡도: O(N)
- 더 나은 알고리즘: 그리디 알고리즘과 큐 또는 스택을 활용한 단순화된 매칭 알고리즘

### 잘한 점

- collections.defaultdict를 활용하여 각 사람이 선물을 주고자 하는 대상과 받은 대상의 관계를 적절히 파악하려 시도함
- 전체 시간 복잡도가 O(N)으로 유지되어 타임 리미트 내에 동작 가능함

### 개선할 점

- 조건 분기가 지나치게 복잡하여 가독성이 떨어지고 엣지 케이스 발생 시 오류를 찾기 어려움
- 변수명(same, start, target 등)이 직관적이지 않아 코드의 흐름을 이해하기 힘듦
- 자기 자신을 선물로 지정하는 엣지 케이스나 마지막 남은 원소 처리 로직이 견고하지 못함

### 상세 피드백

제출된 코드는 문제의 요구사항인 최대 만족 수(k)를 구하고 유효한 순열 배열 b를 구성하기 위해 여러 조건 분기를 사용하고 있습니다. 시간 복잡도 측면에서는 O(N)으로 전체 테스트케이스 합이 2*10^5인 제한 안에 잘 동작할 수 있지만, 코드 내의 복잡한 조건문과 리스트 조작으로 인해 가독성이 크게 떨어지고 디버깅이 어려워 보입니다. 특히 중복 선택된 간선들을 처리하는 과정에서 엣지 케이스 처리(자기 자신을 가리키게 되는 경우 등)가 복잡하게 얽혀 있어 코드의 유지보수성이 낮습니다. 더 직관적인 접근 방식으로는, 먼저 각 사람이 원하는 선물을 최대한 배정하되 중복이 발생하는 경우를 체크하고, 아직 선물을 받지 못한 사람(target)과 중복으로 양도해야 하는 사람(start)을 각각 큐나 리스트에 모은 뒤 순차적으로 연결해 주는 방식이 있습니다. 이 과정에서 마지막 남은 원소가 자기 자신을 가리키는 고립된 1-사이클이 생기지 않도록 주의하여 처리하면 훨씬 간결하고 안전한 코드를 작성할 수 있습니다.
