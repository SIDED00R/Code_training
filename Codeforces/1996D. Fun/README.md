## 문제 설명

두 정수 $n$과 $x$가 주어졌을 때, $ab + ac + bc \le n$이고 $a + b + c \le x$를 만족하는 양의 정수 순서쌍 ($a,b,c$)의 개수를 구하시오. 순서가 중요하며 (예: ($1, 1, 2$)와 ($1, 2, 1$)은 다른 것으로 취급함), $a$, $b$, $c$는 엄격하게 $0$보다 커야 함에 유의하라.

## 입력

첫 번째 줄에는 테스트 케이스의 개수를 나타내는 단일 정수 $t$ ($1 \leq t \leq 10^4$)가 주어집니다. 각 테스트 케이스는 두 정수 $n$과 $x$ ($1 \leq n,x \leq 10^6$)를 포함합니다. 모든 테스트 케이스에 대한 $n$의 합은 $10^6$을 넘지 않으며, 모든 테스트 케이스에 대한 $x$의 합도 $10^6$을 넘지 않는다는 것이 보장됩니다.

## 출력

$ab + ac + bc \le n$ 이고 $a + b + c \le x$ 를 만족하는 양의 정수 삼중조 ($a,b,c$)의 개수인 단 하나의 정수를 출력한다.

## 코드 리뷰

- 효율성: 보통
- 시간복잡도: O(min(N, X^2))
- 더 나은 알고리즘: O(N log N) 또는 O(N sqrt(N)) 시간 복잡도를 가지는 수학적 최적화 풀이를 사용할 수 있습니다. a와 b에 대해 이중 루프를 돌고 c의 상한을 수학적으로 O(1)에 계산하는 방식입니다. n의 최댓값이 10^6이므로 a를 1부터 n까지, b를 1부터 n/a까지 순회하면 전체 연산 횟수는 n log n이 되어 파이썬에서도 시간 내에 넉넉하게 통과합니다.

### 잘한 점

- 중첩 반복문 안에서 c의 최댓값을 min 함수를 통해 O(1)에 계산하여 불필요한 삼중 루프를 피했습니다.
- max_b가 1보다 작을 경우 조기에 반복문을 탈출(break)하는 최적화를 적용했습니다.
- 각 테스트 케이스별로 입력을 받아 빠르게 처리하는 구조를 갖추었습니다.

### 개선할 점

- 함수 인자명(x, y)과 문제의 변수(n, x)가 반대로 전달되어 가독성이 떨어집니다.
- 함수 내부에 있는 y >= (x * x) // 3 조건은 문제의 수학적 관계와 맞지 않아 오답이나 예기치 않은 동작을 유발할 수 있습니다.
- 파이썬의 높은 반복문 오버헤드를 고려할 때, 10^6 범위의 입력을 처리하기에 알고리즘의 실제 연산 횟수가 다소 많을 수 있습니다.

### 상세 피드백

제출하신 코드는 a와 b에 대한 이중 루프를 사용하며, b의 최댓값을 조기에 제한(메모이제이션 또는 브레이크)하고 c의 상한을 min(limit1, limit2)로 빠르게 계산하여 불필요한 연산을 줄이려고 시도했습니다. 하지만 변수명 매칭에서 입력 파라미터(x, y)가 문제의 n과 x와 혼동될 여지가 있고, 특히 파이썬의 반복문 오버헤드로 인해 최악의 경우 시간 제한 내에 통과하기에 다소 빠듯할 수 있습니다. 또한 첫 번째 조건문인 if y >= (x * x) // 3 부분은 문제 조건과 맞지 않는 잘못된 최적화일 수 있습니다. 문제의 제약 조건인 sum(n) <= 10^6과 sum(x) <= 10^6을 활용하려면, a의 범위를 1부터 x까지, b의 범위를 1부터 n // a까지로 설정하는 표준적인 O(N log N) 브루트포스 접근법이 구현도 쉽고 안전합니다.
