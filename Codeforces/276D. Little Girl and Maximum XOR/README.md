## 문제 설명

어린 소녀는 비트 연산과 관련된 문제를 아주 좋아합니다. 다음은 그 문제 중 하나입니다. 두 정수 $l$과 $r$이 주어집니다. $l \le a \le b \le r$을 만족하는 모든 정수 쌍 $a$와 $b$에 대하여 ![수식](https://espresso.codeforces.com/9b77fab607849cb208cd8aab633b62d894fc3358.png)의 값들을 생각해 봅시다. 여러분의 임무는 고려한 모든 값 중 최댓값을 찾는 것입니다. 식 ![수식](https://espresso.codeforces.com/b364f2e04c665b78b924ec10666327a4ef4635bc.png)은 정수 $x$와 $y$에 대해 비트별 배타적 논리합(bitwise XOR) 연산을 수행함을 의미합니다. 이 연산은 모든 현대 프로그래밍 언어에 존재하며, 예를 들어 $C$++과 $Java$에서는 " ^ "로, $Pascal$에서는 " xor "로 표현됩니다.

## 입력

단일 줄에는 공백으로 구분된 두 정수 $l$과 $r$ ($1 \le l \le r \le 10^{18}$)이 주어집니다. C++에서 64비트 정수를 읽거나 쓸 때 `%lld` 지정자를 사용하지 마세요. 대신 `cin`, `cout` 스트림이나 `%I64d` 지정자를 사용하는 것이 좋습니다.

## 출력

한 줄에 단 하나의 정수를 출력합니다. 모든 정수 쌍 $a$, $b$ ($l \le a \le b \le r$)에 대한 ![수식](https://espresso.codeforces.com/9b77fab607849cb208cd8aab633b62d894fc3358.png)의 최댓값을 구하세요.

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: O(log(R))

### 잘한 점

- 비트 연산의 특성을 잘 이해하고 그리디한 접근으로 문제를 해결함
- 시간 복잡도가 O(log R)로 매우 효율적임
- l과 r이 같은 경우 등 엣지 케이스를 올바르게 처리함

### 개선할 점

- 거듭제곱 연산(2 ** idx)을 사용하여 비트 시프트 연산(1 << idx)에 비해 미세하게 비효율적일 수 있음
- 변수명(idx, now)이 역할을 명확하게 드러내지 못해 주석이나 추가 설명이 있으면 더 좋았을 것임

### 상세 피드백

제출한 코드는 주어진 범위 `[l, r]`에서 비트 연산을 활용하여 최적의 XOR 값을 매우 효율적으로 찾아내고 있습니다. $l$과 $r$의 이진수 표현을 최상위 비트부터 비교하면서 처음으로 값이 달라지는 지점을 찾는 방식은 이 문제의 핵심을 정확히 관통하는 그리디 접근법입니다. 시간 복잡도는 $r$의 비트 수에 비례하므로 최대 60여 번의 연산만 수행하여 $O(\log R)$의 매우 빠른 속도를 자랑합니다. 공간 복잡도 또한 $O(1)$로 최적입니다. 다만, 파이썬의 `2 ** idx` 연산 대신 비트 시프트 연산(`1 << idx`)을 사용하면 더욱 직관적이고 빠르게 구현할 수 있습니다. 엣지 케이스인 $l = r$인 경우에도 `answer = 0`이 올바르게 출력되도록 잘 설계되어 있습니다. 전반적으로 코드의 가독성이 좋고 알고리즘을 정확하게 이해하고 작성한 훌륭한 풀이입니다.
