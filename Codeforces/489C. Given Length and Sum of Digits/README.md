## 문제 설명

양의 정수 $m$과 음이 아닌 정수 $s$가 주어집니다. 여러분의 과제는 길이가 $m$이고 각 자릿수의 합이 $s$인 수들 중에서 가장 작은 수와 가장 큰 수를 구하는 것입니다. 구하려는 수는 앞에 불필요한 0이 없는, 10진법으로 표현된 음이 아닌 정수여야 합니다.

## 입력

입력의 한 줄에는 정수 쌍 $m$, $s$ ($1 ≤ m ≤ 100, 0 ≤ s ≤ 900$)가 주어진다 — 이는 구하는 수들의 길이와 자릿수의 합을 의미한다.

## 출력

출력에는 요구된 조건을 만족하는 음이 아닌 정수 두 개를 — 먼저 가능한 최솟값, 그 다음 가능한 최댓값을 — 쌍으로 출력하시오. 조건을 만족하는 숫자가 존재하지 않는 경우에는 " -1 -1 " (따옴표 제외)이라는 숫자 쌍을 출력하시오.

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: O(m) 시간, O(m) 공간 (길이 m짜리 문자열 생성)

### 잘한 점

- 모든 경계 조건(m=1&&s=0, s=0, 9*m<s)을 정확히 분리하여 처리함
- min/max 숫자를 O(m) 문자열 조립만으로 구성하는 효율적인 그리디 로직을 정확히 구현함
- 자리수 경계(m-2-count 등)가 항상 0 이상이 되도록 수학적으로 일관되게 설계되어 인덱스 오류가 발생하지 않음

### 개선할 점

- 변수명(left, count)을 low/high 계산에 반복 재사용하면서 의미가 바뀌어 가독성이 떨어짐
- 핵심 수식 유도 과정에 대한 주석이 전혀 없어 코드만 보고 로직을 이해하기 어려움
- if/elif 분기 구조가 다소 복잡해 보여서, m==1 특수 케이스를 일반 케이스에 통합하면 코드가 더 간결해질 수 있음

### 상세 피드백

이 문제는 사실상 DP라기보다 그리디 구성(construction) 문제입니다. 제출 코드는 바로 그 그리디 전략을 그대로 구현했습니다: 최솟값은 맨 앞자리를 가능한 가장 작게 하고(리딩제로 방지를 위해 최소 1), 나머지 자리를 뒤쪽부터 9로 최대한 채워서 합을 맞추고, 최댓값은 앞쪽부터 9로 최대한 채우고 남는 합을 중간 자리 하나에 몰아넣는 방식입니다. m, s의 범위(각각 최대 100, 900)가 매우 작기 때문에 시간/공간 복잡도 측면에서 더 최적화할 필요가 전혀 없고, O(m) 수준이면 충분합니다. 로직을 직접 손으로 몇 가지 케이스(m=2,s=15 / m=2,s=9 / m=2,s=1 / m=100,s=900)에 대해 검증해보면 모두 올바른 값을 출력하며, 경계 조건(9*m < s, s==0, m==1 and s==0)도 빠짐없이 분기 처리되어 있습니다. 다만 변수명이 축약적(left, count 등을 low/high 양쪽 계산에서 재사용)이라 처음 읽을 때 혼동될 수 있고, 핵심 수식(left = s - (m-1)*9, count = (s-1)//9 등)이 왜 그렇게 도출되는지에 대한 주석이 전혀 없어 유지보수나 교육적 관점에서 가독성이 떨어집니다. 전체적으로 알고리즘 선택과 구현 정확성은 매우 우수하나, 코드 설명력 측면에서 개선 여지가 있습니다.
