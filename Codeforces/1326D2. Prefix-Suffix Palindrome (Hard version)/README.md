## 문제 설명

이 문제는 이 문제의 하드 버전입니다. 두 버전의 차이점은 문자열 길이의 합과 테스트 케이스 수에 대한 제약 조건뿐입니다. 이 태스크의 모든 버전을 해결해야만 훌륭한 해킹(hack)을 수행할 수 있습니다. 알파벳 소문자로 이루어진 문자열 $s$가 주어집니다. 다음 조건을 만족하는 가장 긴 문자열 $t$를 찾으세요: $t$의 길이는 $s$의 길이를 초과하지 않습니다. $t$는 팰린드롬(palindrome)입니다. $t = a + b$ (여기서 " $+$ "는 문자열 이어붙이기를 나타냄)를 만족하는 두 문자열 $a$와 $b$(비어 있을 수도 있음)가 존재하며, $a$는 $s$의 접두사(prefix)이고 $b$는 $s$의 접미사(suffix)입니다.

## 입력

입력은 여러 개의 테스트 케이스로 구성됩니다. 첫 번째 줄에는 테스트 케이스의 개수를 나타내는 단일 정수 $t$ ($1 \leq t \leq 10^5$)가 주어집니다. 이어지는 $t$개의 줄에는 각각 하나의 테스트 케이스가 설명되어 있습니다. 각 테스트 케이스는 알파벳 소문자로만 이루어진 비어 있지 않은 문자열 $s$입니다. 모든 test case에 대한 문자열 길이의 합은 $10^6$을 넘지 않는 것이 보장됩니다.

## 출력

각 테스트 케이스마다, 위에서 설명한 조건을 만족하는 가장 긴 문자열을 출력한다. 가능한 정답이 여러 개인 경우, 그중 아무거나 하나를 출력한다.

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: O(N) (N은 문자열의 길이)

### 잘한 점

- 양 끝이 일치하는 부분을 먼저 털어내어 남은 탐색 범위를 줄이는 직관적인 그리디 접근법을 사용했습니다.
- Manacher 알고리즘을 활용해 중앙 부분의 최대 팰린드롬 접두사/접미사를 O(N) 시간에 정확하게 찾아냈습니다.
- sum of lengths over all test cases <= 10^6 인 엄격한 제약 조건을 O(N) 시간복잡도로 훌륭히 통과할 수 있도록 구현했습니다.

### 개선할 점

- Manacher 알고리즘을 구현할 때 문자열 변환 및 배열 생성 과정에서 불필요한 메모리 할당이 발생할 수 있어 Python 환경에서 메모리 최적화 여지가 약간 있습니다.
- 변수명(bp, bs, k 등)이 짧아서 직관적으로 어떤 역할을 하는지 한눈에 파악하기는 조금 아쉽습니다.

### 상세 피드백

제출하신 코드는 Manacher 알고리즘과 그리디 접근법을 훌륭하게 결합하여 문제를 해결했습니다. 먼저 문자열의 양 끝에서부터 서로 같은 문자가 나오는 동안을 최대한 뜯어낸 뒤, 남은 중앙 부분에 대해 Manacher 알고리즘을 적용하여 접두사이거나 접미사인 가장 긴 팰린드롬을 찾아내는 아이디어는 매우 효율적이며 시간복잡도 O(N)을 만족합니다. 문제의 제약 조건(총 길이 10^6 이하) 내에서 Python으로도 충분히 시간 내에 통과할 수 있는 최적의 알고리즘 중 하나를 선택하셨습니다. 코드의 가독성도 좋으며, 엣지케이스 처리도 잘 구현되어 있습니다.
