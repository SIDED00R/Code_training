## 문제 설명

어떤 자연수 p와 q가 있을 때, 만일 p를 q로 나누었을 때 나머지가 0이면 q는 p의 약수이다.
6을 예로 들면
6 ÷ 1 = 6 … 0
6 ÷ 2 = 3 … 0
6 ÷ 3 = 2 … 0
6 ÷ 4 = 1 … 2
6 ÷ 5 = 1 … 1
6 ÷ 6 = 1 … 0
그래서 6의 약수는 1, 2, 3, 6, 총 네 개이다.
두 개의 자연수 N과 K가 주어졌을 때, N의 약수들 중 K번째로 작은 수를 출력하는 프로그램을 작성하시오.

## 입력

첫째 줄에 N과 K가 빈칸을 사이에 두고 주어진다. N은 1 이상 10,000 이하이다. K는 1 이상 N 이하이다.

## 출력

첫째 줄에 N의 약수들 중 K번째로 작은 수를 출력한다. 만일 N의 약수의 개수가 K개보다 적어서 K번째 약수가 존재하지 않을 경우에는 0을 출력하시오.

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: O(sqrt(N) + d log d)  (d는 약수의 개수, sqrt(N)으로 약수를 찾고 그 중 정렬에 d log d가 추가로 소요됨)
- 더 나은 알고리즘: 약수를 찾을 때 작은 약수(num)는 리스트 앞쪽에 순서대로 쌓이고, 큰 약수(n//num)는 역순으로 쌓이는 성질을 이용하면 sorted() 없이도 두 리스트를 합치는 것만으로 정렬된 약수 리스트를 O(sqrt(N))에 만들 수 있습니다. 다만 N<=10000이라는 제약상 체감 성능 차이는 거의 없습니다.

### 잘한 점

- N의 제곱근까지만 탐색하여 약수를 구하는 효율적인 알고리즘을 사용함
- 완전제곱수인 경우 num과 n//num이 같아지는 상황을 if num != n // num 조건으로 정확히 처리하여 중복 삽입을 방지함
- 약수 개수가 K보다 적을 때 0을 출력하는 예외 처리가 명확하게 구현됨

### 개선할 점

- sqrt(N) 방식으로 약수를 구하면 이미 반정렬된 상태(작은 약수는 오름차순, 큰 약수는 역순)를 활용할 수 있는데 sorted()를 추가로 호출하여 약간의 비효율이 발생함
- 변수명 ans_list, num 등이 의미를 명확히 드러내지 못함(divisors, i 등으로 개선 가능)
- N<=10000이라는 작은 제약 조건을 고려하면 O(N) 단순 브루트포스로도 충분히 통과 가능한 문제인데, 굳이 sqrt(N) 최적화를 적용해 코드 복잡도가 약간 증가함(다만 이는 장점으로도 볼 수 있음)

### 상세 피드백

이 코드는 N이 10,000 이하로 작다는 제약을 고려했을 때 이미 충분히 효율적인 O(sqrt(N)) 약수 탐색 기법을 올바르게 적용했습니다. num과 n//num을 동시에 찾아 완전제곱수(num == n//num)일 때 중복 삽입을 막는 처리도 정확하게 되어 있습니다. 다만 약수를 찾은 뒤 다시 sorted()로 정렬하는 과정은 약간의 추가 비용인데, sqrt(N) 방식으로 약수를 구하면 작은 약수는 오름차순으로, 큰 약수는 내림차순으로 쌓이는 패턴을 이용해 정렬 없이도 병합할 수 있어 더 깔끔한 설계가 가능합니다. 또한 N<=10000, K<=N이라는 입력 제약을 생각하면 사실 O(N) 단순 브루트포스로 1부터 N까지 모두 검사해도 시간 내에 충분히 통과하므로, 이 문제의 난이도(브론즈3)에 비해서는 다소 과한 최적화를 적용한 느낌도 있습니다. 하지만 이는 단점이 아니라 오히려 좋은 습관으로, 더 큰 입력에서도 안전하게 동작하는 코드를 작성한 것으로 평가할 수 있습니다. len(s_list) < k 조건으로 약수 개수가 부족한 경우 0을 출력하는 예외 처리도 명확하게 구현되어 있어 문제의 요구사항을 정확히 충족합니다.
