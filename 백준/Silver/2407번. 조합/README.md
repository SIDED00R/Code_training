# [Silver III] 조합 - 2407

[문제 링크](https://boj.kr/2407)

## 성능 요약

메모리: - KB, 시간: - ms

## 분류

`수학`, `조합론`, `임의 정밀도 / 큰 수 연산`

## 제출 일자

2026년 11월 25일 07:16:38

## 문제 설명

_nC_m을 출력한다.

## 입력

n과 m이 주어진다. (5 ≤ n ≤ 100, 5 ≤ m ≤ 100, m ≤ n)

## 출력

_nC_m을 출력한다.

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: O(min(m, n-m)) 시간, O(1)~O(n) 공간 (math.comb 내부 구현 기준)

### 잘한 점

- math.comb를 사용하여 직접 팩토리얼을 계산하는 것보다 효율적이고 간결하게 조합을 구현함
- Python의 임의 정밀도 정수를 활용해 큰 수 연산을 별도 구현 없이 안전하게 처리함
- 코드가 매우 간결하고 가독성이 높음

### 개선할 점

- 변수명 n, m이 문제 설명과 일치하여 가독성에는 문제없지만, 입력값에 대한 별도 검증 로직이 없음(다만 제약 조건상 필요하지 않음)
- math.comb가 없는 환경(Python 3.8 미만)에서는 동작하지 않는다는 점을 고려하지 않음

### 상세 피드백

이 문제는 n, m이 최대 100으로 매우 작은 범위이기 때문에 사실상 어떤 방법을 써도 시간 초과가 날 수 없는 문제입니다. 핵심은 '큰 수 연산'을 언어가 기본적으로 지원하는가인데, Python은 임의 정밀도 정수를 기본 지원하므로 오버플로우 걱정이 전혀 없습니다. 여기에 더해 math.comb를 사용한 것은 매우 좋은 선택입니다. math.comb는 CPython 내부적으로 최적화된 C 레벨 구현(분자/분모를 점진적으로 곱하고 나누는 방식)으로 동작하여, 직접 팩토리얼을 계산해 나누는 것보다 중간 값이 작고 연산이 빠릅니다. 직접 구현한다면 파스칼의 삼각형(DP)이나 math.factorial(n)//(math.factorial(m)*math.factorial(n-m)) 방식도 가능하지만, 둘 다 math.comb보다 느리거나 불필요하게 큰 중간값을 다룹니다. 코드가 매우 간결하고 표준 라이브러리를 적절히 활용한 모범적인 풀이입니다. 다만 입력 형식 검증이나 예외 처리는 없지만, 백준 문제 특성상 입력이 항상 명시된 제약을 만족하므로 문제가 되지 않습니다.
