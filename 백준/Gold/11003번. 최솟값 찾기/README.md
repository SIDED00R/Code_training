## 문제 설명

N개의 수 A_1, A_2, ..., A_N과 L이 주어진다.
D_i = A_{i-L+1} ~ A_i 중의 최솟값이라고 할 때, D에 저장된 수를 출력하는 프로그램을 작성하시오. 이때, i ≤ 0 인 A_i는 무시하고 D를 구해야 한다.

## 입력

첫째 줄에 N과 L이 주어진다. (1 ≤ L ≤ N ≤ 5,000,000)
둘째 줄에는 N개의 수 A_i가 주어진다. (-10^9 ≤ A_i ≤ 10^9)

## 출력

첫째 줄에 D_i를 공백으로 구분하여 순서대로 출력한다.

## 코드 리뷰

- 효율성: 보통
- 시간복잡도: 시간복잡도 O(N), 공간복잡도 O(N)

### 잘한 점

- 슬라이딩 윈도우 최솟값 문제에 적합한 모노토닉 덱 기법을 정확히 구현하여 O(N) 시간복잡도를 달성함
- sys.stdin.readline과 결과를 한 번에 join하여 출력하는 방식으로 입출력 오버헤드를 줄이려는 시도가 있음

### 개선할 점

- N이 최대 5,000,000에 달하는 만큼 input() 대신 sys.stdin.buffer.read().split()을 사용하는 등 더 적극적인 입력 최적화가 필요할 수 있음 (현재 구현도 TLE 가능성 있음)
- 출력 끝에 개행 문자가 없어 일부 채점 환경에서 문제가 될 수 있음
- 변수명이 간결하긴 하나 answer 대신 result처럼 더 명확한 이름을 쓰거나, L=1 같은 극단적 케이스에 대한 주석/설명이 없어 가독성 측면에서 약간의 보완이 아쉬움

### 상세 피드백

알고리즘 측면에서는 모노토닉 덱(monotonic deque)을 이용한 슬라이딩 윈도우 최솟값 기법을 정확하게 구현했습니다. 각 인덱스를 덱에 넣을 때 현재 값보다 크거나 같은 원소를 뒤에서부터 제거해 덱을 오름차순으로 유지하고, 윈도우 범위를 벗어난 앞쪽 인덱스를 popleft로 제거하는 방식은 이 문제의 정석적인 O(N) 풀이이며 우선순위 큐(O(N log N))보다 더 효율적입니다. 로직 자체는 교과서적으로 깔끔합니다.

다만 N이 최대 5,000,000이라는 점을 고려하면 Python/CPython 구현의 상수 비용이 문제가 될 수 있습니다. input().split()으로 한 줄 전체를 읽는 것은 맞는 방향이지만, 이 정도 규모에서는 sys.stdin.buffer.read().split()으로 바이트 단위로 읽는 것이 더 빠릅니다. 또한 매 반복마다 덱의 append/pop/popleft 연산과 list 인덱싱이 N번씩 반복되므로 CPython 인터프리터 오버헤드가 누적되어 TLE 위험이 있습니다. 가능하다면 sys.stdin.buffer로 입력을 받고, map/int 변환을 최소화하거나 PyPy 제출을 고려하는 것이 실전적으로 더 안전합니다. 출력 시 개행 문자(\n)가 없는 점도 플랫폼에 따라 문제가 될 수 있어 추가하는 것이 안전합니다.
