## 문제 설명

문자열 s가 주어졌을 때, 중복된 문자가 없는 부분 문자열 중 가장 긴 것의 길이를 구하세요.

 

예제 1:

입력: s = "abcabcbb"
출력: 3
설명: 답은 "abc"이며, 길이는 3입니다. "bca"와 "cab"도 정답이 될 수 있습니다.

예제 2:

입력: s = "bbbbb"
출력: 1
설명: 답은 "b"이며, 길이는 1입니다.

예제 3:

입력: s = "pwwkew"
출력: 3
설명: 답은 "wke"이며, 길이는 3입니다.
"pwke"는 부분 수열(subsequence)이며 부분 문자열(substring)이 아니므로 답이 될 수 없다는 점에 유의하세요.

 

제약 조건:

0 <= s.length <= 10^5

s는 영문자, 숫자, 기호 및 공백으로 구성됩니다.

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: 시간복잡도: O(N), 공간복잡도: O(min(N, K)) - K는 문자 집합 크기

### 잘한 점

- 슬라이딩 윈도우 알고리즘을 정확히 이해하고 구현하여 O(N) 시간복잡도를 달성함
- deque와 defaultdict를 활용해 왼쪽/오른쪽 포인터 이동과 문자 빈도 관리를 깔끔하게 처리함
- 빈 문자열 등 엣지케이스에서도 별도 분기 없이 자연스럽게 정답을 반환함

### 개선할 점

- 변수명 stack이 실제로는 큐(deque)로 사용되고 있어 혼동을 줄 수 있음 (window나 queue가 더 적절함)
- 문자의 마지막 등장 인덱스를 저장하는 해시맵 방식(포인터 점프)에 비해 왼쪽 포인터를 한 칸씩만 이동시키므로 로직이 약간 더 복잡하고 직관성이 떨어짐
- letter 대신 c, dic 대신 char_count처럼 더 명확한 변수명을 사용하면 가독성이 개선될 수 있음

### 상세 피드백

이 풀이는 슬라이딩 윈도우(투 포인터) 기법을 deque와 defaultdict를 조합하여 정확하게 구현했습니다. 각 문자를 한 번씩만 방문하면서(오른쪽 포인터로 append) 중복이 발생하면 왼쪽에서부터 제거(popleft)하는 방식으로 O(N) 시간복잡도를 달성했습니다. 이는 이 문제에 대해 이론적으로 최적에 가까운 접근법입니다. 다만 일반적으로 슬라이딩 윈도우 문제에서는 deque 대신 왼쪽 포인터(인덱스)를 정수로 관리하는 방식이 더 흔하고 메모리 효율적입니다. 현재 방식은 deque에 실제 문자를 저장하므로 popleft 시 O(1)이지만, 정수 포인터 방식에 비해 약간의 오버헤드(deque 객체 생성/관리)가 있습니다. 또한 dic[letter] > 1 체크를 통해 정확히 중복된 문자만 제거하는 것이 아니라, 중복 문자가 사라질 때까지 왼쪽에서 하나씩 제거하는 로직이 조금 우회적입니다. 더 일반적인 구현은 문자의 마지막 등장 인덱스를 딕셔너리에 저장해두고, 새 문자가 나타났을 때 윈도우 시작점을 바로 그 인덱스+1로 점프시키는 방식(O(N), 상수 시간 단축)입니다. 하지만 현재 코드도 amortized O(N)이므로 성능상 큰 차이는 없습니다. 빈 문자열 처리도 반복문이 실행되지 않아 answer=0을 정확히 반환하므로 엣지케이스도 잘 처리됩니다.
