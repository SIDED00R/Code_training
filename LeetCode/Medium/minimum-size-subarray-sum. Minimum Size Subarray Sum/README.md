## 문제 설명

양의 정수로 이루어진 배열 nums와 양의 정수 target이 주어질 때, 합이 target 이상이 되는 부분 배열의 최소 길이를 반환하세요. 그러한 부분 배열이 없다면 대신 0을 반환하세요.

 

예제 1:

입력: target = 7, nums = [2,3,1,2,4,3]
출력: 2
설명: 부분 배열 [4,3]이 문제 조건에서 최소 길이를 가집니다.

예제 2:

입력: target = 4, nums = [1,4,4]
출력: 1

예제 3:

입력: target = 11, nums = [1,1,1,1,1,1,1,1]
출력: 0

 

제약 조건:

1 <= target <= 10^9

1 <= nums.length <= 10^5

1 <= nums[i] <= 10^4

 

심화 문제: O(n) 솔루션을 찾아냈다면, 시간 복잡도가 O(n log(n))인 또 다른 솔루션을 코딩해 보세요.

## 코드 리뷰

- 효율성: 보통
- 시간복잡도: 시간 O(N), 공간 O(N)
- 더 나은 알고리즘: 시간복잡도는 이미 최적(O(N))이지만, prefix sum 배열을 전부 메모리에 저장할 필요 없이 변수 하나로 현재 윈도우의 합(window_sum)을 누적/차감하는 전형적인 투 포인터(sliding window) 방식을 쓰면 공간복잡도를 O(1)로 줄일 수 있습니다. 참고로 문제의 Follow-up에서 요구하는 O(N log N) 풀이는 prefix sum 배열 + 각 시작 인덱스마다 이분탐색(bisect)으로 target을 만족하는 끝 인덱스를 찾는 방식이며, 이 코드는 사실상 그보다 더 빠른 O(N) 투 포인터를 구현한 것입니다.

### 잘한 점

- 투 포인터 로직이 정확하게 구현되어 있어 O(N) 시간복잡도로 정답을 도출함
- 구간합을 prefix sum으로 미리 계산해두어 구간합 계산 자체는 O(1)로 빠르게 수행됨
- 해가 없는 경우(answer가 갱신되지 않은 경우) 0을 반환하는 엣지케이스를 올바르게 처리함

### 개선할 점

- 모든 원소가 양수라는 제약을 활용하면 prefix sum 배열 없이 윈도우 합 누적만으로 O(1) 공간에 구현 가능한데 불필요하게 O(N) 공간을 사용함
- front_point/back_point라는 변수명이 실제 역할(오른쪽/왼쪽 포인터)과 직관적으로 매칭되지 않아 코드 가독성을 떨어뜨림
- answer의 초기값을 1e9라는 float 매직 넘버로 설정해 의도 파악이 어렵고, float('inf')나 len(nums)+1 등 더 명확한 값을 쓰는 것이 좋음

### 상세 피드백

제출한 코드는 prefix sum 배열을 미리 구성한 뒤 두 포인터(front_point, back_point)를 이용해 조건을 만족하는 최소 구간을 탐색하는 방식입니다. 각 포인터가 배열을 한 번씩만 순회하므로 전체 시간복잡도는 O(N)으로 이 문제의 최적 해법과 동일합니다. 다만 prefix sum 배열을 별도로 생성하면서 O(N)의 추가 공간을 사용하는데, 이 문제는 모든 원소가 양수라는 조건 덕분에 윈도우 합을 변수 하나로 누적/차감하는 고전적인 sliding window로 O(1) 공간에 풀 수 있어 다소 불필요한 메모리 사용입니다. 또한 front_point가 실제로는 윈도우의 오른쪽(끝) 포인터, back_point가 왼쪽(시작) 포인터 역할을 하는데 이름만 보면 반대로 해석되기 쉬워 가독성이 떨어집니다. answer 초기값을 1e9(float)로 둔 점도 동작은 문제없지만 float('inf')나 len(nums)+1처럼 의도가 명확한 값을 쓰는 것이 더 바람직합니다. 로직 자체는 back_point가 front_point를 넘어서지 않음을 보장하는 invariant가 잘 성립하여 정확성에는 문제가 없고, 모든 주어진 예제와 엣지케이스(해가 없는 경우 0 반환)도 올바르게 처리됩니다.
