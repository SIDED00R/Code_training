## 문제 설명

n개의 노드로 이루어진 네트워크가 있으며, 노드는 1부터 n까지 번호가 매겨져 있습니다. 또한 방향이 있는 간선 형태의 이동 시간 목록인 times가 주어지며, times[i] = (ui, vi, wi)에서 ui는 출발 노드, vi는 도착 노드, wi는 신호가 출발 노드에서 도착 노드까지 이동하는 데 걸리는 시간입니다.

주어진 노드 k에서 신호를 보냅니다. n개의 노드 모두가 신호를 수신하는 데 걸리는 최소 시간을 반환하세요. 만약 n개의 노드 모두가 신호를 수신하는 것이 불가능하다면, -1을 반환하세요.

 

예제 1:

입력: times = [[2,1,1],[2,3,1],[3,4,1]], n = 4, k = 2
출력: 2

예제 2:

입력: times = [[1,2,1]], n = 2, k = 1
출력: 1

예제 3:

입력: times = [[1,2,1]], n = 2, k = 2
출력: -1

 

제약 조건:

1 <= k <= n <= 100

1 <= times.length <= 6000

times[i].length == 3

1 <= ui, vi <= n

ui != vi

0 <= wi <= 100

모든 쌍 (ui, vi)는 유일합니다. (즉, 중복되는 간선은 없습니다.)

## 코드 리뷰

- 효율성: 비효율적
- 시간복잡도: O(V*E) 최악의 경우 (V=n, E=len(times)), 공간복잡도 O(V+E)
- 더 나은 알고리즘: 가중치가 모두 0 이상(0 <= wi <= 100)이므로 Dijkstra's Algorithm을 heapq(우선순위 큐)로 구현하면 O(E log V)에 해결 가능합니다. 현재 코드는 스택을 이용해 완화(relaxation)를 반복하는 방식으로, 이는 사실상 SPFA(Bellman-Ford의 큐 최적화 변형)와 동일한 구조입니다. 음수 가중치가 없는 상황에서 SPFA는 Dijkstra보다 이론적으로도, 실무적으로도 비효율적이며 최악의 경우 O(V*E)로 저하될 수 있습니다. heapq를 사용해 (거리, 노드)를 push/pop하며 방문한 노드를 재방문하지 않도록 처리하면 훨씬 안정적인 성능을 보장할 수 있습니다.

### 잘한 점

- 그래프를 인접 리스트로 구성하고 완화(relaxation) 조건을 올바르게 적용하여 정답을 도출함
- 모든 노드 도달 불가능 시 -1을 반환하는 엣지케이스 처리가 명확함
- defaultdict를 활용해 그래프 구성 코드가 간결함

### 개선할 점

- 우선순위 큐(heapq) 대신 일반 스택을 사용하여 Dijkstra의 그리디 성질을 활용하지 못하고 SPFA에 가까운 비효율적 방식으로 동작함 (최악의 경우 O(V*E))
- weight를 별도 딕셔너리로 분리 관리하여 조회 및 코드 구조가 불필요하게 복잡해짐 (route에 (v, w) 형태로 통합하는 것이 더 자연스러움)
- visited 변수명이 실제로는 '최단 거리'를 의미하는데, 이름이 역할을 정확히 반영하지 못해 가독성이 떨어짐

### 상세 피드백

이 코드는 다익스트라 문제를 스택 기반의 완화(relaxation) 반복, 즉 SPFA 방식으로 풀었습니다. N<=100, E<=6000이라는 작은 제약 조건 덕분에 통과는 가능하지만, 알고리즘적으로는 최적이 아닙니다.

핵심 문제는 우선순위 큐(min-heap)를 사용하지 않고 일반 스택(DFS 순서)으로 노드를 처리한다는 점입니다. 이 때문에 한 노드가 여러 번 스택에 들어가 불필요하게 재처리될 수 있고, 최악의 경우 시간복잡도가 O(V*E)까지 치솟습니다. 가중치가 모두 비음수이므로 heapq를 활용한 Dijkstra를 쓰면 O(E log V)로 훨씬 효율적이며, 이미 확정된(최단거리가 고정된) 노드는 재방문하지 않는 식으로 로직도 더 명확해집니다.

또한 weight를 별도의 딕셔너리로 분리해서 관리하는 것도 다소 번거롭습니다. route[u]에 (v, w) 튜플을 직접 저장하면 조회 비용과 코드 복잡도를 줄일 수 있습니다. visited 배열의 네이밍도 실제로는 '거리(distance)'를 저장하는 역할이라 dist로 바꾸는 것이 가독성에 좋습니다.

정답 로직 자체(모든 노드가 도달 가능한지 확인 후 최대값 반환)는 올바르게 구현되어 있고, -1 처리도 적절합니다. 다만 알고리즘 선택이 문제의 태그(Dijkstra, Heap)와 맞지 않아 효율성 면에서는 개선이 필요합니다.
