## 문제 설명

연결 리스트가 주어지면, 인접한 두 노드씩 서로 교환하고 그 머리(head)를 반환하세요. 리스트 노드의 값을 수정하지 않고 문제를 해결해야 합니다 (즉, 노드 자체만 변경할 수 있습니다.)

 

예제 1:

입력: head = [1,2,3,4]

출력: [2,1,4,3]

설명:

예제 2:

입력: head = []

출력: []

예제 3:

입력: head = [1]

출력: [1]

예제 4:

입력: head = [1,2,3]

출력: [2,1,3]

 

제약 조건:

리스트의 노드 개수는 [0, 100] 범위입니다.

0 <= Node.val <= 100

## 코드 리뷰

- 효율성: 비효율적
- 시간복잡도: 시간 O(N), 공간 O(N) (원래는 O(1) 공간으로 가능한데 매번 새 노드를 생성하므로 N)
- 더 나은 알고리즘: dummy 노드를 하나 두고 prev, first, second 포인터를 이용해 기존 노드들의 next 포인터만 재배선하는 반복문(iterative) 방식이나, head와 head.next를 교환한 뒤 재귀 호출하는 방식을 사용하면 O(N) 시간, O(1) 추가 공간(재귀의 경우 O(N/2) 콜스택)으로 해결 가능하며, 문제가 요구하는 '노드 값은 변경 금지, 노드 자체만 재배치' 조건도 올바르게 지킬 수 있습니다.

### 잘한 점

- 빈 리스트와 홀수 개의 노드가 있는 엣지케이스를 모두 올바르게 처리함
- 전체 순회가 O(N)으로 시간복잡도 자체는 나쁘지 않음

### 개선할 점

- 문제의 핵심 제약(노드 값 변경 금지, 노드 자체만 재배치)을 위반하고 매번 새 ListNode를 생성해 값만 복사함
- 스택과 while True 무한루프를 사용해 단순한 2개씩 교환 로직을 불필요하게 복잡하게 구현함
- 변수명(now, out, stack, answer)이 역할을 명확히 드러내지 못해 가독성이 낮음
- 원래 노드를 재사용하지 않으므로 공간복잡도가 O(1)이 아닌 O(N)으로 비효율적임

### 상세 피드백

이 풀이는 결과적으로 올바른 출력을 내지만, 문제의 핵심 제약인 '노드의 값을 수정하지 말고 노드 자체(포인터)만 재배치하라'는 요구사항을 지키지 않고 있습니다. head.val을 꺼내 스택에 쌓은 뒤 ListNode(out)으로 새 노드를 매번 생성하는 방식은 사실상 값만 복사하는 것과 동일하며, 원래 연결리스트의 노드 객체들은 전혀 재사용되지 않습니다. LeetCode 채점기는 출력된 값의 순서만 확인하기 때문에 Accepted가 나오지만, 이는 문제의 의도(Linked List 태그, 포인터 조작 연습)를 비껴간 풀이입니다. 또한 스택과 while True 무한루프, 매번 새 노드 생성 등의 구조는 단순한 두 칸씩 교환 문제에 비해 과도하게 복잡합니다. 표준적인 방법인 dummy 노드 + 3개 포인터(prev, first, second) 반복 교환이나 재귀적 교환 방식을 사용하면 코드가 훨씬 짧고 명확해지며, 노드 자체를 재배치하는 본래 의도에도 맞습니다. 변수명(now, out, stack)도 의미가 모호해 가독성이 떨어지고, 2개씩 짝지어 스택에 넣는 로직이 직관적으로 '교환'을 표현하지 못해 코드를 이해하는데 시간이 걸립니다.
