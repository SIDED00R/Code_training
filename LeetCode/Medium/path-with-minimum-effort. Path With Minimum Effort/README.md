## 문제 설명

당신은 다가오는 등산을 준비하는 하이커입니다. rows x columns 크기의 2차원 배열 heights가 주어지며, heights[row][col]은 셀 (row, col)의 높이를 나타냅니다. 당신은 왼쪽 상단 셀인 (0, 0)에 위치해 있으며, 오른쪽 하단 셀인 (rows-1, columns-1)로 이동하고자 합니다 (즉, 0-인덱스 기준). 위, 아래, 왼쪽, 오른쪽으로 이동할 수 있으며, 최소 노력(effort)이 필요한 경로를 찾고자 합니다.

어떤 경로의 노력은 그 경로에서 연속된 두 셀 사이의 높이 차이의 절댓값 중 최댓값입니다.

왼쪽 상단 셀에서 오른쪽 하단 셀로 이동하는 데 필요한 최소 노력을 반환하세요.

 

예제 1:

입력: heights = [[1,2,2],[3,8,2],[5,3,5]]
출력: 2
설명: [1,3,5,3,5] 경로는 연속된 셀 사이의 최대 절댓값 차이가 2입니다.
이는 최대 절댓값 차이가 3인 [1,2,2,2,5] 경로보다 더 좋습니다.

예제 2:

입력: heights = [[1,2,3],[3,8,4],[5,3,5]]
출력: 1
설명: [1,2,3,4,5] 경로는 연속된 셀 사이의 최대 절댓값 차이가 1이며, 이는 [1,3,5,3,5] 경로보다 더 좋습니다.

예제 3:

입력: heights = [[1,2,1,1,1],[1,2,1,2,1],[1,2,1,2,1],[1,2,1,2,1],[1,1,1,2,1]]
출력: 0
설명: 이 경로는 아무런 노력도 필요하지 않습니다.

 

제약 조건:

rows == heights.length

columns == heights[i].length

1 <= rows, columns <= 100

1 <= heights[i][j] <= 10^6

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: 시간: O(R*C*log(R*C)) (R=행, C=열, 각 셀이 최대 4번 힙에 push/pop), 공간: O(R*C) (visited 배열 + 힙)
- 더 나은 알고리즘: 현재 풀이(변형 Dijkstra)도 이미 최적에 가까운 접근입니다. 대안으로는 (1) 이분탐색 + BFS/DFS: effort 값 X를 이분탐색하면서 모든 인접 칸의 높이 차이가 X 이하인 그래프에서 (0,0)->(R-1,C-1) 도달 가능 여부를 BFS로 검사하는 방식으로 O(R*C*log(maxHeight))에 해결 가능하고, (2) Union-Find(Kruskal 유사): 모든 엣지를 높이 차이 기준으로 정렬한 뒤 작은 것부터 합쳐가며 시작점과 끝점이 연결되는 순간의 가중치를 답으로 하는 O(E log E) 방식도 가능합니다. 다만 이 셀 크기(최대 100x100)에서는 세 방법 모두 충분히 빠르므로 현재 Dijkstra 방식이 실용적으로 가장 무난합니다.

### 잘한 점

- 표준 Dijkstra를 '합 최소화'가 아닌 '최대값 최소화' 문제에 맞게 정확히 변형하여 적용함
- 힙에서 pop되는 순서가 non-decreasing임을 이용해 목적지 도달 시 즉시 종료하는 최적화를 적용함
- O(R*C*log(R*C))로 문제의 제약조건(최대 100x100)에 충분히 효율적인 성능을 보임

### 개선할 점

- visited라는 변수명이 실제 의미(최소 effort 거리)를 정확히 반영하지 못해 가독성이 떨어짐
- heapq에 list 대신 tuple을 사용하는 것이 Python 관례에 더 부합하고 약간의 성능 이점이 있음
- answer 변수가 본질적으로 weight와 동일한 값을 추적하므로 다소 중복적이며, 이에 대한 설명 주석이 없어 왜 필요한지 이해하기 어려움

### 상세 피드백

이 풀이는 '최대 간선 가중치를 최소화하는 경로 찾기' 문제를 변형된 Dijkstra 알고리즘으로 정확하게 해결하고 있습니다. 일반적인 Dijkstra가 거리의 합을 최소화하는 것과 달리, 여기서는 경로 상 최대 가중치를 최소화하도록 relax 조건(diff < visited[ni][nj])을 수정한 것이 핵심 아이디어이며 이는 정확합니다. 힙에서 pop될 때 non-decreasing 순서로 나오므로 도착점에 도달하면 즉시 반환해도 되고, 'answer = max(answer, weight)' 처리도 안전장치로 들어가 있어 논리적으로 문제가 없습니다. 다만 몇 가지 개선점이 있습니다. 첫째, visited라는 변수명이 실제로는 '해당 셀까지 도달하는 최소 effort'를 의미하므로 min_effort나 dist 같은 이름이 더 명확합니다. 둘째, heap에 list([0,0,0])를 push하는데 Python 관례상 tuple을 사용하는 것이 더 적절하고 약간의 성능 이점도 있습니다. 셋째, 1x1 그리드 같은 엣지 케이스는 잘 처리되지만 이에 대한 주석이나 테스트가 없어 가독성 면에서 아쉽습니다. 전반적으로 알고리즘 선택과 구현은 훌륭하며, 변수명과 자료구조 선택만 다듬으면 더 좋은 코드가 될 것입니다.
