## 문제 설명

연결 리스트의 head가 주어졌을 때, 리스트의 끝에서부터 n^th 번째 노드를 제거하고 그 head를 반환하세요.

 

예제 1:

입력: head = [1,2,3,4,5], n = 2
출력: [1,2,3,5]

예제 2:

입력: head = [1], n = 1
출력: []

예제 3:

입력: head = [1,2], n = 1
출력: [1]

 

제약 조건:

리스트에 있는 노드의 개수는 sz입니다.

1 <= sz <= 30

0 <= Node.val <= 100

1 <= n <= sz

 

후속 질문: 한 번의 순회로 이를 해결할 수 있나요?

## 코드 리뷰

- 효율성: 보통
- 시간복잡도: 시간 O(N), 공간 O(N) (재귀 호출 스택으로 인한 추가 공간)
- 더 나은 알고리즘: Two Pointers(빠른/느린 포인터) 기법을 사용하면 O(N) 시간, O(1) 공간으로 해결할 수 있습니다. dummy 노드에서 시작한 fast 포인터를 n+1번 먼저 이동시킨 뒤, fast와 slow를 동시에 끝까지 이동시키면 slow가 삭제할 노드의 직전 노드를 가리키게 됩니다. 이는 문제의 Follow-up에서 요구하는 'one pass, O(1) 공간' 조건을 완벽히 만족합니다.

### 잘한 점

- dummy 노드를 사용하여 head 노드를 삭제해야 하는 엣지 케이스를 깔끔하게 처리함
- 재귀의 반환값을 이용해 노드의 뒤에서부터 순서를 계산하는 아이디어가 창의적이고 코드가 간결함

### 개선할 점

- 재귀 호출로 인해 O(N)의 추가 콜스택 공간을 사용하여, 두 포인터 기법에 비해 공간 효율성이 떨어짐
- 리스트 크기가 매우 커질 경우 Python의 재귀 깊이 제한에 걸릴 수 있어 확장성이 부족함
- 문제의 알고리즘 태그(Two Pointers)와 Follow-up 요구사항(O(1) 공간)을 고려하지 않은 접근 방식

### 상세 피드백

이 풀이는 재귀를 이용해 리스트의 끝에서부터 거리를 계산하고, 역순으로 돌아오면서 n+1번째 노드에서 next를 건너뛰는 방식으로 정답을 정확히 구현했습니다. dummy 노드를 사용해 head를 삭제해야 하는 엣지 케이스(n == sz)도 깔끔하게 처리했고, 로직 자체는 올바르며 읽기도 쉽습니다. 다만 알고리즘 태그에 명시된 'Two Pointers' 기법을 사용하지 않고 재귀를 선택함으로써, 콜 스택에 O(N)만큼의 추가 공간을 사용하게 되었습니다. LeetCode의 이 문제는 제약 조건(sz <= 30)이 작아 재귀 깊이에 의한 성능 문제는 발생하지 않지만, sz가 수만~수십만 단위로 커지는 상황을 가정하면 재귀 깊이 제한(Python 기본 1000)에 걸려 RecursionError가 발생할 위험이 있습니다. 또한 문제의 Follow-up에서 명시적으로 '한 번의 순회, 가능하면 O(1) 공간'을 요구하고 있으므로, 전통적인 두 포인터(fast/slow) 방식으로 구현하는 것이 이 문제의 의도에 더 부합합니다. 전체적으로 정답은 맞지만, 최적해 관점에서는 공간복잡도 측면에서 개선 여지가 있는 'ok' 수준의 풀이입니다.
