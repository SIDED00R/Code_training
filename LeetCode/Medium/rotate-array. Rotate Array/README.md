## 문제 설명

정수 배열 nums가 주어지면, 배열을 오른쪽으로 k번 회전시키세요. 여기서 k는 음이 아닌 수입니다.

 

예제 1:

입력: nums = [1,2,3,4,5,6,7], k = 3
출력: [5,6,7,1,2,3,4]
설명:
오른쪽으로 1번 회전: [7,1,2,3,4,5,6]
오른쪽으로 2번 회전: [6,7,1,2,3,4,5]
오른쪽으로 3번 회전: [5,6,7,1,2,3,4]

예제 2:

입력: nums = [-1,-100,3,99], k = 2
출력: [3,99,-1,-100]
설명:
오른쪽으로 1번 회전: [99,-1,-100,3]
오른쪽으로 2번 회전: [3,99,-1,-100]

 

제약 조건:

1 <= nums.length <= 10^5

-2^31 <= nums[i] <= 2^31 - 1

0 <= k <= 10^5

 

추가 질문:

가능한 한 많은 풀이 방법을 생각해 보세요. 이 문제를 푸는 방법은 최소 세 가지 이상 있습니다.

O(1)의 추가 공간만 사용해서 제자리(in-place)에서 풀 수 있나요?

## 코드 리뷰

- 효율성: 보통
- 시간복잡도: 시간복잡도 O(N), 공간복잡도 O(N)
- 더 나은 알고리즘: Follow-up에서 요구하는 O(1) 추가 공간 풀이로는 '3단계 뒤집기(reverse)' 기법이 적합합니다. 전체 배열을 뒤집고, 앞의 k개를 다시 뒤집고, 나머지 n-k개를 다시 뒤집으면 슬라이싱 없이 in-place로 O(N) 시간, O(1) 공간에 회전을 완성할 수 있습니다. 또는 cyclic replacement(순환 치환) 방식으로도 O(1) 공간에 구현 가능합니다.

### 잘한 점

- 코드가 간결하고 한눈에 이해하기 쉬움
- k % len(nums)로 k가 배열 길이보다 큰 경우를 올바르게 처리함
- move=0일 때(k가 배열 길이의 배수인 경우)도 별도 분기 없이 자연스럽게 처리됨

### 개선할 점

- 슬라이싱으로 새 리스트를 생성하므로 O(N) 추가 공간을 사용해 follow-up의 O(1) 공간 요구사항을 만족하지 못함
- Two Pointers 태그가 암시하는 reverse 기법이나 cyclic replacement 같은 in-place 알고리즘을 사용하지 않아 알고리즘 학습 측면에서 아쉬움

### 상세 피드백

이 풀이는 Python 슬라이싱을 활용해 `nums[-move:] + nums[:-move]`로 회전된 배열을 만들고 nums[:]에 대입하는 방식입니다. 로직은 정확하며 k=0, len(nums)==1 같은 경계 조건도 자연스럽게 처리됩니다(move=0일 때 nums[-0:]이 전체 배열, nums[:-0]이 빈 리스트가 되어 원본이 그대로 유지됨). 다만 nums[:] 슬라이스 할당 자체는 in-place로 보이지만, 우변의 nums[-move:]와 nums[:-move] 슬라이싱 과정에서 매번 새로운 리스트가 생성되므로 실제로는 O(N)의 추가 공간을 사용합니다. 이 문제는 명시적으로 'in-place O(1) 추가 공간' 풀이를 follow-up으로 요구하고 있고, 태그에도 Two Pointers가 포함되어 있어 reverse 기법이나 cyclic replacement 같은 포인터 기반 O(1) 공간 풀이를 의도한 문제입니다. 현재 코드는 정답은 맞지만 문제가 의도한 핵심 학습 포인트(공간 최적화)를 놓치고 있어 educational 관점에서는 개선 여지가 큽니다. 코드 자체는 매우 간결하고 가독성이 좋으며, move 변수명도 의미가 명확합니다.
