## 문제 설명

문자열 s와 정수 k가 주어집니다. 문자열에서 아무 문자나 선택하여 다른 대문자 알파벳으로 바꿀 수 있습니다. 이 연산은 최대 k번까지 수행할 수 있습니다.

위 연산을 수행한 후 얻을 수 있는, 같은 문자로 이루어진 가장 긴 부분 문자열의 길이를 반환하세요.

 

예시 1:

입력: s = "ABAB", k = 2
출력: 4
설명: 두 개의 'A'를 두 개의 'B'로 바꾸거나 그 반대로 바꿉니다.

예시 2:

입력: s = "AABABBA", k = 1
출력: 4
설명: 중간에 있는 'A' 하나를 'B'로 바꿔서 "AABBBBA"를 만듭니다.
부분 문자열 "BBBB"가 가장 길게 반복되는 문자를 가지며, 길이는 4입니다.
이 답을 얻을 수 있는 다른 방법도 존재할 수 있습니다.

 

제약 조건:

1 <= s.length <= 10^5

s는 대문자 알파벳으로만 구성됩니다.

0 <= k <= s.length

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: 시간복잡도: O(N), 공간복잡도: O(1) (26개 크기의 고정 배열만 사용)

### 잘한 점

- O(N) 시간, O(1) 공간으로 최적에 가까운 Sliding Window 풀이를 정확하게 구현함
- max_count를 줄이지 않아도 정답이 보장된다는 핵심 아이디어를 올바르게 활용함
- 변수명(count, left, max_count, answer)이 명확하여 가독성이 좋음
- ord() 연산을 이용한 26개 알파벳 카운팅 방식이 간결하고 효율적임

### 개선할 점

- max_count가 윈도우 축소 시에도 갱신되지 않는 이유에 대한 주석이 없어, 처음 보는 사람은 정확성을 의심할 수 있음
- k=0이나 길이 1인 문자열 같은 특수 입력에 대한 명시적 처리/테스트 언급이 없어 엣지케이스 검증 흔적이 부족함
- s가 비어있는 경우(제약상 발생하지 않지만) answer 초기값 0 반환이 적절한지에 대한 고려가 코드에 드러나지 않음

### 상세 피드백

이 풀이는 Sliding Window 기법을 활용한 전형적인 O(N) 최적해입니다. `max_count`가 윈도우를 줄일 때 갱신되지 않아 실제보다 과대평가될 수 있지만, 이는 윈도우 크기가 더 커지지 않는 이상 answer 값에 영향을 주지 않는다는 점을 이용한 잘 알려진 트릭으로, 정확성에 문제가 없습니다. right 포인터가 한 번 전진할 때 left도 최대 한 번만 전진하므로 전체 반복은 O(N)이며, count 배열이 26 크기로 고정되어 공간복잡도도 O(1)입니다. Medium 난이도의 Sliding Window 문제에 대해 시간/공간 모두 최적에 가까운 접근이며, 더 효율적인 알고리즘으로 개선할 여지가 거의 없습니다. 코드도 간결하고 변수명이 직관적이어서 가독성이 좋습니다. 다만 `max_count`가 의미상 '현재 윈도우 내 최다 빈도'가 아니라 '지금까지 관측된 최다 빈도'라는 점을 주석으로 남기면 코드 이해도가 더 높아질 것입니다.
