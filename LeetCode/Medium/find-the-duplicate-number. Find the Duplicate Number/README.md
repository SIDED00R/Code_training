## 문제 설명

각 정수가 [1, n] 범위에 포함되는 n + 1개의 정수를 담고 있는 배열 nums가 주어집니다.

nums에는 오직 하나의 중복된 숫자만 존재합니다. 이 중복된 숫자를 반환하세요.

배열 nums를 수정하지 않고, 오직 일정한(constant) 추가 공간만 사용하여 문제를 해결해야 합니다.

 

예제 1:

입력: nums = [1,3,4,2,2]
출력: 2

예제 2:

입력: nums = [3,1,3,4,2]
출력: 3

예제 3:

입력: nums = [3,3,3,3,3]
출력: 3

 

제약 조건:

1 <= n <= 10^5

nums.length == n + 1

1 <= nums[i] <= n

nums에 있는 모든 정수는 정확히 한 번 나타나며, 단 하나의 정수만 두 번 이상 나타납니다.

 

후속 질문:

nums에 중복된 숫자가 적어도 하나 존재해야 함을 어떻게 증명할 수 있을까요?

선형 시간 복잡도로 문제를 해결할 수 있나요?

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: O(N) 시간, O(1) 공간

### 잘한 점

- 제약조건(배열 수정 불가, O(1) 공간)을 모두 만족하면서 O(N) 시간복잡도를 달성하는 최적의 알고리즘 선택
- Floyd's Cycle Detection의 2단계(사이클 탐지 → 시작점 탐색)를 정확하고 간결하게 구현함
- 불필요한 자료구조나 추가 변수 없이 slow/fast 두 포인터만으로 깔끔하게 문제를 해결함

### 개선할 점

- 알고리즘의 동작 원리(배열을 함수 그래프로 보는 관점, 사이클 시작점이 중복값과 일치하는 이유)에 대한 주석이 없어 코드만으로는 이해하기 어려울 수 있음
- 변수명 slow, fast는 관례적이지만 문제 맥락에서는 의미가 다소 모호하므로, 간단한 docstring이나 인라인 주석으로 각 단계의 목적을 설명하면 가독성이 향상됨

### 상세 피드백

이 풀이는 Floyd's Cycle Detection(토끼와 거북이) 알고리즘을 정확하게 구현한 최적 해법입니다. 배열의 각 인덱스를 '다음 노드를 가리키는 포인터'로 해석하여 nums[i] 관계를 연결 리스트의 간선처럼 취급하고, 중복된 값이 존재하면 반드시 사이클이 생긴다는 점을 이용합니다. 문제의 제약조건인 '배열을 수정하지 않고 상수 공간만 사용'과 '선형 시간복잡도'를 동시에 만족시키는 사실상 유일한 접근법이라는 점에서 매우 적합합니다.

구현도 정확합니다. 1단계에서 slow는 한 칸씩, fast는 두 칸씩 이동하며 만날 때까지 반복하고(cycle detection), 2단계에서 slow를 시작점으로 재설정한 뒤 slow와 fast를 같은 속도로 이동시켜 사이클의 시작점(=중복값)을 찾는 전형적인 투 포인터 패턴을 따르고 있습니다. while True + break 구조도 가독성을 해치지 않는 수준입니다.

다만 Floyd's Algorithm이 왜 동작하는지(배열을 함수 f(x)=nums[x]로 보고 사이클 탐지 문제로 변환했다는 점), 그리고 왜 이 사이클의 시작점이 정확히 중복값과 일치하는지에 대한 수학적 근거를 주석으로 남겼다면 유지보수성과 교육적 가치가 더 높았을 것입니다. 입력이 항상 유효하다는 제약(중복값이 정확히 하나 존재) 덕분에 별도의 예외처리는 필요 없습니다.
