## 문제 설명

정수 배열 nums와 정수 k가 주어질 때, 합이 k와 같은 부분배열의 총 개수를 반환하세요.

부분배열은 배열 내에서 연속된 비어 있지 않은 원소들의 시퀀스입니다.

 

예제 1:

입력: nums = [1,1,1], k = 2
출력: 2

예제 2:

입력: nums = [1,2,3], k = 3
출력: 2

 

제약 조건:

1 <= nums.length <= 2 * 10^4

-1000 <= nums[i] <= 1000

-10^7 <= k <= 10^7

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: 시간복잡도 O(N), 공간복잡도 O(N)

### 잘한 점

- O(N) 시간복잡도로 최적의 해시맵+접두사합 기법을 정확히 적용함
- dic[0]=1 초기화로 처음부터 시작하는 서브배열 케이스를 놓치지 않고 처리함
- 변수명이 직관적이고 코드가 간결하여 가독성이 높음

### 개선할 점

- defaultdict 조회 시 존재하지 않는 키가 자동으로 0으로 생성되어 불필요한 메모리가 소모될 수 있음 (dic.get(p_sum-k, 0) 권장)
- 입력 검증이나 엣지케이스(빈 배열 등)에 대한 별도 주석이나 설명이 없어 코드만으로 의도를 파악하기엔 약간 불친절할 수 있음

### 상세 피드백

접두사 합(prefix sum)과 해시맵을 결합한 전형적이고 최적화된 풀이입니다. 각 원소를 순회하며 현재까지의 누적합 p_sum을 구하고, p_sum - k 값이 이전에 몇 번 등장했는지를 딕셔너리에서 조회하여 정답에 더하는 방식은 이 문제의 표준적인 O(N) 해법입니다. dic[0] = 1로 초기화한 것도 누적합 자체가 k와 같은 경우(즉 배열의 맨 앞부터 시작하는 서브배열)를 올바르게 처리하기 위한 핵심적인 부분으로 정확히 구현되어 있습니다. defaultdict를 사용해 조회 시 키 에러를 방지한 점도 적절합니다. 다만 answer += dic[p_sum - k] 부분에서 defaultdict 특성상 존재하지 않는 키를 조회만 해도 해당 키가 0으로 딕셔너리에 추가되는 부수효과가 있는데, 정답에는 영향이 없지만 공간을 약간 더 사용하게 되므로 .get(p_sum - k, 0)을 쓰는 것이 미세하게 더 깔끔할 수 있습니다. 전체적으로 음수와 0을 포함한 값, 큰 k 범위 등 제약조건도 해시맵 기반 접근이라 문제없이 처리됩니다. 변수명(p_sum, dic, answer)도 의미가 명확해 가독성이 좋고, 코드가 간결합니다. 이 문제에서 요구하는 최적 시간복잡도를 정확히 달성한 풀이로 추가로 개선할 알고리즘적 여지는 거의 없습니다.
