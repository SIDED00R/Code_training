## 문제 설명

pow(x, n)을 구현하세요. 이는 x의 n제곱(즉, x^n)을 계산합니다.

 

예제 1:

입력: x = 2.00000, n = 10
출력: 1024.00000

예제 2:

입력: x = 2.10000, n = 3
출력: 9.26100

예제 3:

입력: x = 2.00000, n = -2
출력: 0.25000
설명: 2^-2 = 1/2^2 = 1/4 = 0.25

 

제약 조건:

-100.0 < x < 100.0

-2^31 <= n <= 2^31-1

n은 정수입니다.

x가 0이 아니거나 n > 0입니다.

-10^4 <= x^n <= 10^4

## 코드 리뷰

- 효율성: 비효율적
- 시간복잡도: O(1) (내부적으로 C 라이브러리 함수를 호출하므로 사실상 상수 시간이지만, 알고리즘적으로 직접 구현한 것이 아님)
- 더 나은 알고리즘: Divide and Conquer(빠른 거듭제곱, Fast Exponentiation)를 직접 구현해야 합니다. n을 2로 나누어가며 x^n = (x^(n/2))^2 형태로 재귀 또는 반복적으로 계산하면 O(log N) 시간복잡도로 해결할 수 있습니다. 예: n이 음수면 x = 1/x, n = -n으로 변환 후 재귀적으로 half = myPow(x, n//2)를 구해 n이 짝수면 half*half, 홀수면 half*half*x를 반환하는 방식입니다. 이렇게 하면 Math/Recursion 태그가 요구하는 핵심 알고리즘을 실제로 구현하게 됩니다.

### 개선할 점

- 문제의 핵심 알고리즘인 분할정복(빠른 거듭제곱)을 전혀 구현하지 않고 내장 함수에 의존함
- Math, Recursion 태그가 요구하는 학습 목표(재귀적 사고, 시간복잡도 최적화)를 다루지 않음
- n이 매우 큰 음수(예: INT_MIN)일 때의 오버플로우 처리나 x=0, n=0 같은 엣지케이스에 대한 명시적 고려가 코드에 드러나지 않음
- 실전 코딩 인터뷰 상황이라면 이런 풀이는 문제 회피로 간주되어 감점 요인이 될 수 있음

### 상세 피드백

제출한 코드는 파이썬 내장 함수인 math.pow(x, n)을 그대로 호출하여 문제를 우회하고 있습니다. 이 방식은 LeetCode 채점 시스템에서는 정답으로 통과할 수 있지만, 이 문제가 의도하는 학습 목표인 '빠른 거듭제곱(Fast Power) 알고리즘'을 전혀 구현하지 않은 것입니다. 문제의 알고리즘 태그가 Math와 Recursion으로 명시되어 있는 만큼, 재귀 또는 반복적 분할정복을 이용해 O(log N) 시간에 거듭제곱을 계산하는 로직을 직접 작성하는 것이 이 문제의 핵심입니다. 또한 math.pow는 내부적으로 실수 연산(부동소수점 지수 함수)을 사용하기 때문에 정수 지수에 대해 직접 곱셈 기반으로 계산하는 것보다 정밀도 면에서 미묘한 차이가 발생할 수 있고, n이 음수이거나 극단적인 큰 값(예: n = -2^31)일 때의 처리를 별도로 고민하지 않았다는 점에서 문제 이해도가 부족해 보입니다. 실무나 면접 상황에서는 이런 식으로 언어 내장 함수에 의존하는 풀이는 '문제를 풀지 않았다'고 평가될 가능성이 높습니다. 분할정복 기반의 myPow를 직접 구현하여 O(log N) 복잡도와 재귀 종료 조건, 음수 지수 처리, 오버플로우 방지(n = -n 전에 n이 INT_MIN인 경우 등)를 명시적으로 다뤄보시길 권장합니다.
