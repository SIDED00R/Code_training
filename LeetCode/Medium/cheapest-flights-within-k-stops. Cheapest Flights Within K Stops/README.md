## 문제 설명

n개의 도시가 여러 개의 항공편으로 연결되어 있습니다. 배열 flights가 주어지며, flights[i] = [fromi, toi, pricei]는 도시 fromi에서 도시 toi로 가는 항공편이 있고 그 비용이 pricei임을 나타냅니다.

또한 세 개의 정수 src, dst, k가 주어집니다. 최대 k번의 경유를 사용하여 src에서 dst까지 가는 가장 저렴한 가격을 반환하세요. 그러한 경로가 없다면 -1을 반환하세요.

 

예제 1:

입력: n = 4, flights = [[0,1,100],[1,2,100],[2,0,100],[1,3,600],[2,3,200]], src = 0, dst = 3, k = 1
출력: 700
설명:
그래프는 위 그림과 같습니다.
도시 0에서 3까지 최대 1번 경유하는 최적 경로는 빨간색으로 표시되어 있으며 비용은 100 + 600 = 700입니다.
[0,1,2,3] 도시를 거치는 경로가 더 저렴하지만 2번 경유를 사용하므로 유효하지 않습니다.

예제 2:

입력: n = 3, flights = [[0,1,100],[1,2,100],[0,2,500]], src = 0, dst = 2, k = 1
출력: 200
설명:
그래프는 위 그림과 같습니다.
도시 0에서 2까지 최대 1번 경유하는 최적 경로는 빨간색으로 표시되어 있으며 비용은 100 + 100 = 200입니다.

예제 3:

입력: n = 3, flights = [[0,1,100],[1,2,100],[0,2,500]], src = 0, dst = 2, k = 0
출력: 500
설명:
그래프는 위 그림과 같습니다.
경유 없이 도시 0에서 2까지 가는 최적 경로는 빨간색으로 표시되어 있으며 비용은 500입니다.

 

제약 조건:

2 <= n <= 100

0 <= flights.length <= (n * (n - 1) / 2)

flights[i].length == 3

0 <= fromi, toi < n

fromi != toi

1 <= pricei <= 10^4

두 도시 사이에 여러 개의 항공편은 존재하지 않습니다.

0 <= src, dst, k < n

src != dst

## 코드 리뷰

- 효율성: 보통
- 시간복잡도: 시간복잡도 O((K+1) * E) (E는 간선 수, 최악의 경우 O(K*N^2)), 공간복잡도 O(V+E)
- 더 나은 알고리즘: 현재 구현도 Bellman-Ford를 K+1 라운드로 제한하는 표준 접근과 본질적으로 동일하여 알고리즘 선택 자체는 적절합니다. 다만 구현을 단순화할 수 있습니다: 딕셔너리와 copy.deepcopy 대신 길이 n의 리스트 두 개(prev_cost, cur_cost)를 사용해 매 라운드마다 모든 간선을 한 번씩 순회하는 고전적 Bellman-Ford 방식이 더 간결하고 빠릅니다. 또는 (비용, 현재노드, 사용한 정류장 수) 상태를 갖는 우선순위 큐 기반 변형 다익스트라로도 풀 수 있으나, N<=100 제약에서는 Bellman-Ford 방식이 더 직관적이고 효율적입니다.

### 잘한 점

- 직전 라운드의 거리 값만 사용해 relax함으로써 '최대 K 정류장' 제약을 정확하게 지키는 Bellman-Ford 변형을 올바르게 구현함
- 갱신된 노드만 다음 라운드의 소스로 사용하는 SPFA 스타일 최적화로 불필요한 재탐색을 줄임
- flights가 없거나 dst에 도달 불가능한 경우(-1 반환)를 dict 멤버십 체크로 깔끔하게 처리함

### 개선할 점

- 매 라운드마다 copy.deepcopy를 두 번 호출하는 것은 불필요하게 비용이 크며, 값이 불변 int이므로 dict() 얕은 복사로도 충분함
- route, weight, now_weight, next_weight_dic 등 비슷한 이름의 자료구조가 많아 역할 구분이 어렵고, 핵심 아이디어(라운드별 고정된 소스 거리값 사용)에 대한 주석이 없어 가독성이 낮음
- stack에 같은 노드가 중복으로 들어갈 수 있어 동일 라운드 내에서 같은 노드의 간선을 여러 번 relax하는 비효율이 발생할 수 있음

### 상세 피드백

이 코드는 BFS 레이어 단위로 라운드를 진행하면서 각 라운드에서 '직전 라운드에 갱신된 노드'만 다음 소스로 사용하는 SPFA 스타일의 최적화된 Bellman-Ford입니다. now_weight를 라운드 시작 전에 고정해두고 relax하기 때문에 '최대 K개 정류장' 제약을 올바르게 지키고 있고, 음수 가중치가 없는 그래프이므로 이미 확정된 노드를 재탐색하지 않는 최적화도 정확성을 해치지 않습니다. 다만 매 라운드마다 copy.deepcopy를 두 번씩 호출하는 것은 비용이 큰 연산이며, 값이 모두 int인 딕셔너리이므로 deepcopy 대신 dict() 얕은 복사로 충분합니다. 또한 route, weight, now_weight, next_weight_dic처럼 비슷한 이름의 자료구조가 여러 개 존재해 가독성이 떨어지고, 핵심 로직(라운드마다 누적 dict를 유지하면서 직전 라운드 값만 사용하는 이유)에 대한 주석이 전혀 없어 코드만 봤을 때 의도를 파악하기 어렵습니다. N<=100이라는 제약 덕분에 통과는 문제없지만, 더 큰 입력에서는 deepcopy 오버헤드와 defaultdict 조회 비용이 체감될 수 있습니다. 전반적으로 정답 로직은 견고하지만 구현의 효율성과 가독성 면에서 개선 여지가 있습니다.
