## 문제 설명

정수 x가 주어졌을 때, x가 팰린드롬이면 true를 반환하고, 그렇지 않으면 false를 반환하세요.

 

예제 1:

입력: x = 121
출력: true
설명: 121은 왼쪽에서 오른쪽으로 읽어도, 오른쪽에서 왼쪽으로 읽어도 121입니다.

예제 2:

입력: x = -121
출력: false
설명: 왼쪽에서 오른쪽으로 읽으면 -121입니다. 오른쪽에서 왼쪽으로 읽으면 121-이 됩니다. 따라서 팰린드롬이 아닙니다.

예제 3:

입력: x = 10
출력: false
설명: 오른쪽에서 왼쪽으로 읽으면 01이 됩니다. 따라서 팰린드롬이 아닙니다.

 

제약 조건:

-2^31 <= x <= 2^31 - 1

 

심화 문제: 정수를 문자열로 변환하지 않고 풀 수 있나요?

## 코드 리뷰

- 효율성: 보통
- 시간복잡도: 시간복잡도 O(N), 공간복잡도 O(N) (N은 정수 x의 자릿수)
- 더 나은 알고리즘: 문제의 Follow-up에서 요구하는 대로 문자열 변환 없이 숫자만으로 풀 수 있습니다. 1) 음수는 바로 false 반환. 2) 끝자리가 0이면서 숫자 자체가 0이 아니면 false(앞자리가 0일 수 없으므로 팰린드롬 불가). 3) reversed = 0으로 시작해 x가 reversed보다 커지는 동안 reversed = reversed*10 + x%10, x //= 10을 반복해 절반만 뒤집은 뒤, x == reversed 또는 x == reversed//10(자릿수가 홀수일 때)인지 비교하면 O(log10 N) 시간, O(1) 공간으로 해결 가능합니다.

### 잘한 점

- 문자열 슬라이싱을 활용해 매우 짧고 읽기 쉬운 코드를 작성함
- 음수 입력(-121)에 대해 별도의 조건문 없이도 '-' 기호 비대칭성을 이용해 자연스럽게 False를 반환하도록 처리함
- 기본 테스트 케이스(121, -121, 10)를 모두 통과하는 정확한 로직

### 개선할 점

- 문제의 Follow-up에서 요구한 '문자열 변환 없이 풀기'를 전혀 고려하지 않아 O(1) 공간복잡도로 풀 수 있는 기회를 놓침
- if/return True, return False 패턴이 불필요하게 길며 'return s == s[::-1]' 한 줄로 축약 가능
- 입력값이 매우 큰 정수(2^31 근처)일 경우 문자열 변환 비용이 수학적 접근보다 상대적으로 더 들 수 있음

### 상세 피드백

현재 코드는 정수를 문자열로 변환한 뒤 슬라이싱으로 뒤집어서 원본과 비교하는 방식으로, 로직이 매우 간결하고 음수 케이스(예: -121)도 str() 변환 시 '-' 기호 때문에 자동으로 뒤집었을 때 다르게 나와 정상적으로 False를 반환하므로 별도의 예외 처리 없이도 정답을 맞춥니다. Easy 난이도 문제 치고는 충분히 통과 가능한 깔끔한 풀이이지만, 문제에서 명시적으로 제시한 Follow-up(문자열 변환 없이 풀기)을 고려하지 않았다는 점이 아쉽습니다. Math 태그가 붙어 있는 만큼, 숫자를 역으로 재구성하는 수학적 접근(절반만 뒤집기 기법)을 연습해보면 공간복잡도를 O(1)로 줄이고 더 '수학적인' 풀이를 경험할 수 있습니다. 또한 'if s == s[::-1]: return True / return False' 구문은 'return s == s[::-1]'로 한 줄로 축약 가능해 코드 스타일 면에서도 개선의 여지가 있습니다.
