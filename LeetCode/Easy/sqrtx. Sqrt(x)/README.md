## 문제 설명

음이 아닌 정수 x가 주어졌을 때, x의 제곱근을 소수점 이하를 버림하여 가장 가까운 정수로 반환하라. 반환되는 정수 또한 음이 아니어야 한다.

내장된 지수 함수나 연산자를 사용해서는 안 된다.

예를 들어, c++에서 pow(x, 0.5)를 사용하거나 python에서 x ** 0.5를 사용하지 말라.

 

예제 1:

입력: x = 4
출력: 2
설명: 4의 제곱근은 2이므로 2를 반환한다.

예제 2:

입력: x = 8
출력: 2
설명: 8의 제곱근은 2.82842...이며, 가장 가까운 정수로 내림하므로 2가 반환된다.

 

제약 조건:

0 <= x <= 2^31 - 1

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: O(log x) 시간, O(1) 공간
- 더 나은 알고리즘: 현재 이분 탐색도 충분히 최적에 가깝습니다. 다만 뉴턴-랩슨(Newton's Method)을 쓰면 x_{n+1} = (x_n + x/x_n) / 2 형태의 반복으로 O(log log x) 수준으로 더 빨리 수렴합니다(제곱 수렴). 또한 초기 탐색 범위를 2**32 대신 문제 제약조건(x <= 2^31-1)에 맞춰 46341(약 2^16) 정도로 줄이면 반복 횟수를 살짝 줄일 수 있습니다.

### 잘한 점

- 이분 탐색의 경계 조건(min_num <= max_num)과 종료 후 반환값(max_num)을 정확히 처리하여 off-by-one 오류 없이 올바른 결과를 도출함
- 내장 거듭제곱 함수를 사용하지 않고 mid ** 2 비교만으로 문제 요구사항을 충실히 따름
- 변수명이 직관적이어서 코드 가독성이 좋음

### 개선할 점

- 탐색 범위 상한(2**32)이 문제의 실제 제약조건(x <= 2^31-1)에 비해 불필요하게 크게 설정되어 있어 근거가 불명확한 매직 넘버로 보임
- 각 분기의 의미(탐색 범위를 좌/우로 좁히는 이유)에 대한 주석이 없어 처음 보는 사람이 로직을 이해하는 데 시간이 걸릴 수 있음
- 뉴턴-랩슨 방법 등 더 빠르게 수렴하는 대안에 대한 언급이나 고려가 없음(실무적으로는 큰 문제가 아니지만 학습 관점에서는 아쉬운 부분)

### 상세 피드백

이 풀이는 '가장 큰 mid such that mid^2 <= x'를 찾는 표준 이분 탐색 패턴을 정확히 구현했습니다. min_num <= max_num 조건과 종료 후 max_num을 반환하는 방식은 흔히 발생하는 off-by-one 오류 없이 잘 처리되어 있어 x=0, x=1 같은 경계값도 올바르게 동작합니다.

다만 몇 가지 개선할 점이 있습니다. 첫째, max_num = 2 ** 32는 문제 제약조건(x <= 2^31 - 1)을 고려하면 과도하게 큰 범위입니다. sqrt(2^31-1)는 약 46340이므로 46341 정도로 초기값을 잡아도 충분하며, 이렇게 하면 반복 횟수가 약 32회에서 16회 정도로 줄어듭니다. 큰 차이는 아니지만 매직 넘버의 근거가 불명확해 가독성 측면에서도 아쉽습니다.

둘째, mid ** 2 연산이 x가 매우 클 경우(2^31 근처) 큰 정수 곱셈을 반복하게 되는데 Python에서는 큰 정수 연산이 자동으로 처리되므로 문제는 없지만, 저수준 언어에서는 오버플로우에 주의해야 한다는 점을 알아두면 좋습니다.

셋째, 변수명 min_num, max_num, mid는 명확하고 이해하기 쉬우며 전체적인 로직 흐름도 깔끔합니다. 다만 각 분기(mid**2 > x일 때와 아닐 때)에 대한 짧은 주석을 추가하면 가독성이 더 좋아질 것입니다.

전반적으로 Easy 난이도에 적합한 효율적이고 정확한 풀이이며, 큰 수정 없이도 충분히 좋은 코드입니다.
