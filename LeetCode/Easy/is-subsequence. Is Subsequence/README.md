## 문제 설명

두 문자열 s와 t가 주어졌을 때, s가 t의 부분 수열이면 true를, 그렇지 않으면 false를 반환하세요.

문자열의 부분 수열이란 원래 문자열에서 일부 문자(없을 수도 있음)를 삭제하여 나머지 문자들의 상대적 위치를 유지한 채로 만들어진 새로운 문자열을 의미합니다. (즉, "ace"는 "abcde"의 부분 수열이지만 "aec"는 그렇지 않습니다).

 

예제 1:

입력: s = "abc", t = "ahbgdc"
출력: true

예제 2:

입력: s = "axc", t = "ahbgdc"
출력: false

 

제약 조건:

0 <= s.length <= 100

0 <= t.length <= 10^4

s와 t는 소문자 영어 알파벳으로만 구성됩니다.

 

후속 질문: 만약 s1, s2, ..., sk처럼 들어오는 s가 아주 많고 k >= 10^9이라서, t가 각각의 부분 수열을 포함하는지 하나씩 확인하고 싶다고 가정해봅시다. 이런 경우에는 코드를 어떻게 변경하시겠습니까?

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: 시간복잡도 O(N) (N = len(t)), 공간복잡도 O(1)
- 더 나은 알고리즘: 단일 쿼리에서는 투 포인터가 이미 최적입니다. 다만 문제의 Follow-up처럼 s가 k개(k>=10^9)로 아주 많이 들어오는 경우라면, t를 전처리해서 각 알파벳이 등장하는 인덱스 리스트를 딕셔너리에 저장(O(len(t)))한 뒤, 각 s에 대해 이분 탐색(bisect)으로 다음 등장 위치를 찾는 방식으로 바꾸면 쿼리당 O(len(s) log(len(t)))로 효율을 높일 수 있습니다. DP(두 문자열의 LCS 길이가 min(len(s), len(t))인지 확인하는 방식)로도 풀 수 있지만 O(len(s)*len(t))라서 이 문제에는 투 포인터보다 비효율적입니다.

### 잘한 점

- O(N) 시간, O(1) 공간으로 투 포인터를 활용한 최적에 가까운 풀이
- s가 빈 문자열인 엣지 케이스를 명확히 처리함
- 조건을 만족하면 즉시 반환하여 불필요한 연산을 줄임

### 개선할 점

- len(s)==0 조건을 별도로 처리하지 않고 루프 종료 후 return s_i == len(s)로 통합하면 더 간결해질 수 있음
- 문제의 Follow-up(대량의 s 쿼리 처리)에 대한 고려나 대안 로직이 코드에 반영되어 있지 않음
- 변수명 s_i가 다소 약식 표기라 s_index 등으로 바꾸면 가독성이 더 좋아질 수 있음

### 상세 피드백

투 포인터를 이용해 t를 한 번만 순회하면서 s의 문자를 순서대로 매칭하는 방식으로, 이 문제에 대해 시간복잡도 O(len(t)), 공간복잡도 O(1)의 최적에 가까운 풀이입니다. s가 빈 문자열인 경우를 별도로 처리해 엣지 케이스도 잘 처리했고, 루프 중간에 s_i == len(s)일 때 즉시 True를 반환하여 불필요한 순회를 줄인 점도 좋습니다. 다만 s가 비어있지 않은 경우에도 s_i == len(s) 체크가 루프 안에서만 이루어지므로, for문이 끝난 후 s_i == len(s)인지 다시 체크하는 방식으로 통일하면 if len(s)==0 예외 처리를 생략할 수 있어 코드가 더 간결해질 수 있습니다(예: return s_i == len(s)). 또한 Follow-up에서 요구하는 대규모 쿼리 처리 시나리오에 대한 고려가 코드에 반영되어 있지 않은데, 이는 Easy 문제의 기본 요구사항을 넘어서는 부분이라 필수는 아니지만 면접이나 심화 학습 관점에서는 추가로 고민해볼 만한 포인트입니다. 변수명 s_i는 다소 축약되어 있지만 맥락상 이해하기 쉬운 수준이며, 전체적으로 가독성이 좋고 깔끔한 코드입니다.
