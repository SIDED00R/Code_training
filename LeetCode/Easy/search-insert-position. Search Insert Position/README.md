## 문제 설명

정렬된 서로 다른 정수 배열과 목표 값이 주어졌을 때, 목표 값을 찾으면 그 인덱스를 반환하세요. 찾지 못하면, 순서대로 삽입되었을 때의 인덱스를 반환하세요.

O(log n) 실행 시간 복잡도를 가진 알고리즘을 작성해야 합니다.

 

예제 1:

입력: nums = [1,3,5,6], target = 5
출력: 2

예제 2:

입력: nums = [1,3,5,6], target = 2
출력: 1

예제 3:

입력: nums = [1,3,5,6], target = 7
출력: 4

 

제약 조건:

1 <= nums.length <= 10^4

-10^4 <= nums[i] <= 10^4

nums는 오름차순으로 정렬된 서로 다른 값들을 포함합니다.

-10^4 <= target <= 10^4

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: O(log N) 시간, O(1) 공간

### 잘한 점

- 이분탐색을 통해 O(log n) 시간복잡도 요구사항을 정확히 충족함
- target이 배열에 존재하지 않는 경우에도 삽입 위치를 올바르게 계산하는 하한 탐색 로직을 정확히 구현함
- 추가 자료구조 없이 O(1) 공간만 사용하여 효율적임
- 빈 배열 등 경계 조건에서도 별도 분기 없이 자연스럽게 올바른 결과를 반환함

### 개선할 점

- 변수명 front/back이 이분탐색 관례상 흔히 쓰이는 left/right, lo/hi보다 의도 파악이 다소 느릴 수 있음
- 코드에 주석이 전혀 없어 각 분기(nums[mid] < target vs else)의 의미를 즉시 이해하기 어려울 수 있음
- 타입 힌트는 있지만 함수나 로직에 대한 docstring이 없어 문서화 측면에서 보완 여지가 있음

### 상세 피드백

이 풀이는 전형적인 '하한(lower bound) 이분탐색' 패턴을 정확하게 구현했습니다. front <= back 조건으로 탐색 구간을 유지하고, nums[mid] < target일 때만 front를 전진시키고 그 외(같거나 큰 경우)는 back을 뒤로 당기는 방식은 target이 존재하든 존재하지 않든 올바른 삽입 위치(= target보다 작은 원소의 개수)를 정확히 계산합니다. 문제가 명시한 O(log n) 시간복잡도 요구사항을 정확히 만족하며, 추가 메모리도 사용하지 않아 공간복잡도도 O(1)로 최적입니다. 배열이 비어있는 극단적 케이스(len(nums)==0)에서도 back=-1, front=0으로 시작하여 루프에 진입하지 않고 0을 반환하므로 안전하게 처리됩니다. Easy 난이도 문제에 걸맞게 핵심 알고리즘을 깔끔하게 구현했고, 별도의 수정이나 개선이 필요하지 않은 수준의 완성도 높은 풀이입니다. 다만 변수명을 front/back 대신 관례적으로 많이 쓰이는 left/right(또는 lo/hi)로 바꾸면 다른 개발자들이 더 빠르게 이분탐색 패턴임을 인지할 수 있고, 각 분기의 의도를 설명하는 짧은 주석을 추가하면 가독성이 더 좋아질 것입니다.
