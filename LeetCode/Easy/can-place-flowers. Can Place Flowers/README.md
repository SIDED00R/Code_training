## 문제 설명

길게 이어진 화단이 있고, 일부 칸에는 꽃이 심겨 있고 일부 칸에는 심겨 있지 않습니다. 하지만 인접한 칸에는 꽃을 심을 수 없습니다.

0과 1로 이루어진 정수 배열 flowerbed가 주어지며, 여기서 0은 비어 있음을 의미하고 1은 비어 있지 않음을 의미합니다. 또한 정수 n이 주어질 때, 인접한 칸에 꽃을 심지 않는 규칙을 어기지 않으면서 n개의 새로운 꽃을 flowerbed에 심을 수 있다면 true를, 그렇지 않다면 false를 반환하세요.

 

예제 1:

Input: flowerbed = [1,0,0,0,1], n = 1
Output: true

예제 2:

Input: flowerbed = [1,0,0,0,1], n = 2
Output: false

 

제약 조건:

1 <= flowerbed.length <= 2 * 10^4

flowerbed[i]는 0 또는 1입니다.

flowerbed에는 인접한 두 개의 꽃이 없습니다.

0 <= n <= flowerbed.length

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: O(N) 시간, O(1) 공간 (입력 배열을 제자리에서 수정하므로 추가 공간 거의 없음)

### 잘한 점

- O(N) 시간, O(1) 공간으로 최적의 시간/공간 복잡도를 달성함
- 길이 1인 특수 케이스를 별도로 처리하여 인덱스 범위 초과 오류를 방지함
- 불필요한 추가 자료구조 없이 in-place로 answer를 누적하는 간결한 접근

### 개선할 점

- 입력 리스트(flowerbed)를 함수 내부에서 직접 수정(mutate)하는 부작용이 있어 호출자에게 예상치 못한 영향을 줄 수 있음
- 경계 처리(길이 1, 양 끝단)와 중간 루프 처리가 분리되어 있어 코드 흐름이 다소 복잡하고, 배열 양쪽에 0 패딩을 추가해 통합 루프로 처리하면 더 간결해질 수 있음
- answer가 n 이상이 되는 즉시 조기 반환(early return)하는 최적화가 없어 불필요한 순회가 발생할 수 있음

### 상세 피드백

이 풀이는 Array/Greedy 태그에 맞게 배열을 한 번만 순회하며 O(N) 시간, O(1) 공간으로 문제를 해결하고 있어 알고리즘적으로는 최적입니다. 양 끝단(인덱스 0과 length-1)을 별도로 처리하고 중간 구간을 for 루프로 처리하는 전형적인 경계 처리 방식을 사용했는데, 로직을 추적해보면 길이가 2~3인 짧은 배열에서도 정확하게 동작합니다 (예: [0,0,0] n=2 → True가 정확히 나옴). 다만 코드가 길이 1인 경우, 양 끝단 처리, 중간 루프 이렇게 세 부분으로 분기되어 있어 가독성이 다소 떨어지고, 표준적으로 많이 쓰이는 '배열 양쪽에 0을 패딩한 뒤 하나의 통합 루프로 처리'하는 방식에 비해 코드가 복잡합니다. 또한 입력으로 받은 flowerbed 리스트를 직접 변경(mutate)하는 부작용이 있는데, 이는 호출자가 원본 배열의 재사용을 기대하는 경우 버그로 이어질 수 있어 가급적 지양하는 것이 좋습니다. 조기 종료(answer >= n이면 즉시 True 반환) 최적화를 추가하면 큰 n에 대해 약간의 성능 이점을 얻을 수 있습니다.
