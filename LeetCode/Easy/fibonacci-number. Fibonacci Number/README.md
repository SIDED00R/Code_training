## 문제 설명

피보나치 수는 일반적으로 F(n)으로 표시되며, 0과 1부터 시작하여 각 수가 바로 앞의 두 수의 합이 되는 수열을 이루는데, 이를 피보나치 수열이라고 한다. 즉,

F(0) = 0, F(1) = 1
F(n) = F(n - 1) + F(n - 2), for n > 1.

n이 주어졌을 때, F(n)을 계산하라.

 

예제 1:

입력: n = 2
출력: 1
설명: F(2) = F(1) + F(0) = 1 + 0 = 1.

예제 2:

입력: n = 3
출력: 2
설명: F(3) = F(2) + F(1) = 1 + 1 = 2.

예제 3:

입력: n = 4
출력: 3
설명: F(4) = F(3) + F(2) = 2 + 1 = 3.

 

제약 조건:

0 <= n <= 30

## 코드 리뷰

- 효율성: 보통
- 시간복잡도: O(N) 시간, O(N) 공간
- 더 나은 알고리즘: n <= 30이라는 제약조건상 성능 차이는 미미하지만, 배열 전체를 저장할 필요 없이 두 개의 변수(a, b)만 사용해 O(1) 공간으로 줄일 수 있습니다. 예: a, b = 0, 1; for _ in range(n): a, b = b, a+b; return a. 더 나아가 이론적으로는 행렬 거듭제곱이나 비네 공식(Binet's formula)을 사용하면 O(log N) 시간에 계산할 수 있지만, 이 문제의 제약조건(n<=30)에서는 과도한 최적화이며 실용적 이점이 거의 없습니다.

### 잘한 점

- n=0, n=1의 엣지케이스를 명확하게 분리하여 처리함으로써 로직의 정확성을 보장함
- DP 배열을 이용한 전형적인 상향식 접근으로 코드의 의도가 명확하고 이해하기 쉬움

### 개선할 점

- 직전 두 값만 필요한데도 전체 dp 배열(O(N) 공간)을 할당하여 공간 효율성이 떨어짐
- dp[-1]과 같이 음수 인덱스를 사용하는 것보다 dp[n]처럼 명시적인 인덱스를 사용하는 것이 가독성 측면에서 더 바람직함

### 상세 피드백

이 풀이는 전형적인 상향식(bottom-up) DP 방식으로 n=0, n=1의 base case를 명확히 분리해서 처리하고, 이후 반복문으로 dp 배열을 채워나가는 구조입니다. 로직 자체는 정확하고 이해하기 쉬우며, 피보나치 수열의 점화식을 그대로 반영하고 있어 가독성이 좋습니다. 다만 n의 값을 저장하기 위해 전체 길이 n+1짜리 배열을 할당하는 것은 공간 측면에서 다소 과한 선택입니다. 피보나치 수를 계산할 때는 직전 두 값만 알면 충분하므로, 변수 두 개만 사용하는 O(1) 공간 풀이로 충분히 대체할 수 있습니다. n<=30이라는 작은 제약조건 덕분에 실행 시간이나 메모리 사용량 면에서 실질적인 문제는 발생하지 않지만, 코드 효율성 및 일반화 가능성(더 큰 n에 대응) 측면에서는 개선 여지가 있습니다. 또한 dp[-1]로 마지막 원소에 접근하는 방식은 동작은 하지만 dp[n]으로 명시적으로 작성하는 것이 가독성 면에서 더 좋습니다.
