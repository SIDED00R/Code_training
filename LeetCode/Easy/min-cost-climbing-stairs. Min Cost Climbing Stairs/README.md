## 문제 설명

정수 배열 cost가 주어지며, cost[i]는 계단의 i^th 번째 스텝을 밟는 데 드는 비용입니다.

비용을 지불하면 한 계단 또는 두 계단을 올라갈 수 있습니다.

인덱스 0인 스텝 또는 인덱스 1인 스텝에서 시작할 수 있습니다.

계단의 맨 위, 즉 마지막 스텝을 지나간 위치(인덱스 cost.length)에 도달하는 데 드는 최소 비용을 반환하세요.

 

예제 1:

입력: cost = [10,15,20]
출력: 15
설명: 인덱스 1에서 시작합니다.
- 15를 지불하고 두 계단을 올라가 맨 위에 도달합니다.
총 비용은 15입니다.

예제 2:

입력: cost = [1,100,1,1,1,100,1,1,100,1]
출력: 6
설명: 인덱스 0에서 시작합니다.
- 1을 지불하고 두 계단을 올라가 인덱스 2에 도달합니다.
- 1을 지불하고 두 계단을 올라가 인덱스 4에 도달합니다.
- 1을 지불하고 두 계단을 올라가 인덱스 6에 도달합니다.
- 1을 지불하고 한 계단을 올라가 인덱스 7에 도달합니다.
- 1을 지불하고 두 계단을 올라가 인덱스 9에 도달합니다.
- 1을 지불하고 한 계단을 올라가 맨 위에 도달합니다.
총 비용은 6입니다.

 

제약 조건:

2 <= cost.length <= 1000

0 <= cost[i] <= 999

## 코드 리뷰

- 효율성: 보통
- 시간복잡도: 시간 O(N), 공간 O(N)
- 더 나은 알고리즘: 현재 풀이는 DP 배열 전체(answer)를 저장하지만, 점화식 answer[i] = cost[i] + min(answer[i-1], answer[i-2])은 바로 이전 두 값만 참조합니다. 따라서 변수 두 개(prev1, prev2)만 유지하는 O(1) 공간 DP로 충분히 최적화할 수 있습니다. 예: prev1, prev2 = cost[1], cost[0]부터 시작해 순회하며 업데이트하면 배열 생성 없이 동일한 결과를 얻을 수 있습니다.

### 잘한 점

- 점화식을 정확하게 파악하고 구현하여 로직 자체에 오류가 없음
- 제약 조건(cost.length >= 2)을 활용해 초기값 설정에서 인덱스 에러 없이 안전하게 처리함

### 개선할 점

- O(1) 공간으로 충분한 문제임에도 전체 DP 배열을 저장해 불필요하게 O(N) 공간을 사용함
- 반복문 내에서 min(answer[i-2:i])와 같이 매번 리스트 슬라이싱을 수행해 min(answer[i-1], answer[i-2])보다 비효율적이고 가독성도 떨어짐
- 변수명 answer가 DP 테이블을 나타내는데 의미가 다소 모호함 (dp, min_cost 등이 더 명확함)

### 상세 피드백

이 풀이는 Min Cost Climbing Stairs 문제의 전형적인 DP 점화식 cost[i] + min(dp[i-1], dp[i-2])을 정확히 구현했고, 로직 자체는 올바르며 모든 테스트 케이스를 통과할 것으로 보입니다. 다만 Easy 난이도 DP 문제답게 O(1) 공간으로 풀 수 있음에도 불구하고 cost 길이와 동일한 크기의 answer 배열을 만들어 O(N) 공간을 사용하고 있어 메모리 효율이 떨어집니다. 또한 매 반복에서 min(answer[i-2:i])처럼 슬라이싱으로 길이 2짜리 임시 리스트를 생성하는데, 이는 min(answer[i-1], answer[i-2])로 바로 비교하는 것보다 불필요한 오버헤드(리스트 생성 비용)를 추가합니다. cost.length가 최대 1000이라 성능 문제는 체감되지 않겠지만, 코드 스타일과 공간 복잡도 관점에서는 개선 여지가 분명합니다. 변수명 answer는 DP 배열을 가리키는데 다소 모호하며 dp나 min_cost 같은 이름이 더 직관적입니다. 엣지 케이스(cost.length == 2)는 제약 조건상 항상 성립하므로 별도 처리 없이도 안전하게 동작합니다.
