## 문제 설명

정수 rowIndex가 주어졌을 때, 파스칼의 삼각형의 rowIndex^th (0-인덱스) 행을 반환하세요.

파스칼의 삼각형에서 각 숫자는 다음과 같이 바로 위에 있는 두 숫자의 합입니다:

 

예제 1:

입력: rowIndex = 3
출력: [1,3,3,1]

예제 2:

입력: rowIndex = 0
출력: [1]

예제 3:

입력: rowIndex = 1
출력: [1,1]

 

제약 조건:

0 <= rowIndex <= 33

 

심화 문제: O(rowIndex)의 추가 공간만 사용하도록 알고리즘을 최적화할 수 있나요?

## 코드 리뷰

- 효율성: 보통
- 시간복잡도: 시간: O(rowIndex^2), 공간: O(rowIndex^2)
- 더 나은 알고리즘: 조합 공식을 이용하면 O(rowIndex) 시간과 O(rowIndex) 공간으로 해결 가능합니다. row[i] = row[i-1] * (rowIndex - i + 1) / i 점화식을 이용해 한 줄만 순차적으로 채워나가면 됩니다. 또는 2D 배열 전체를 저장하지 않고, 길이가 rowIndex+1인 리스트 하나만 유지한 채 매 단계마다 '오른쪽에서 왼쪽으로' 갱신하는 in-place 방식(now[j] = now[j] + now[j-1])을 쓰면 O(rowIndex) 추가 공간만으로 Follow-up 조건을 만족시킬 수 있습니다.

### 잘한 점

- i==0, i==1인 엣지케이스를 명확하게 분기 처리하여 작은 입력에서도 안전하게 동작함
- 각 행을 이전 행으로부터 올바른 점화식(now_ans[j] = prev[j] + prev[j+1])으로 정확히 계산하는 핵심 로직이 올바름
- 타입 힌트(list[int])를 사용하여 코드의 가독성과 의도 전달이 명확함

### 개선할 점

- 문제의 Follow-up에서 요구하는 O(rowIndex) 공간 최적화를 만족하지 못하고, 모든 중간 행을 저장하여 O(rowIndex^2) 공간을 사용함
- answer 변수가 2차원 리스트로 쓰이다가 최종적으로 1차원 행만 반환되는 구조라 변수명과 실제 역할이 다소 혼란스러움
- 직전 행만 있으면 되는데 전체 히스토리를 유지하는 것은 메모리 측면에서 불필요한 낭비이며, 한 줄 리스트를 in-place로 갱신하는 더 간결한 구현이 가능함

### 상세 피드백

파스칼의 삼각형을 한 행씩 쌓아가며 마지막 행만 반환하는 전형적인 DP 풀이로, 로직 자체는 정확하고 i=0, i=1 엣지케이스도 잘 처리했습니다. 다만 문제의 Follow-up에서 요구하는 'O(rowIndex) 추가 공간' 조건을 만족하지 못하고 있는 점이 아쇄운 부분입니다. 현재 코드는 answer 리스트에 0번째 행부터 rowIndex번째 행까지 모든 중간 행을 전부 저장하기 때문에 실제 공간 복잡도는 O(rowIndex^2)에 해당합니다(등차수열 합으로 1+2+...+(rowIndex+1) 만큼의 원소를 저장). rowIndex <= 33이라는 제약 때문에 성능 문제는 발생하지 않지만, 알고리즘적으로는 비효율적인 선택입니다. 개선하려면 직전 행 하나만 저장해두고 그 위에서 다음 행을 덮어쓰거나, 조합수 점화식(C(n,k) = C(n,k-1) * (n-k+1)/k)을 이용해 단일 리스트를 순차적으로 갱신하는 방식을 사용하면 됩니다. 또한 answer라는 변수명이 2차원 리스트(모든 행의 집합)로 쓰이다가 최종적으로는 answer[rowIndex]라는 1차원 리스트를 반환하는 구조라 이름이 다소 직관적이지 않습니다. all_rows 같은 이름이 더 명확할 것입니다.
