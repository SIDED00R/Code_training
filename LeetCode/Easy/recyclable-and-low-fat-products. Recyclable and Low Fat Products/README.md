## 문제 설명

Table: Products

+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| product_id  | int     |
| low_fats    | enum    |
| recyclable  | enum    |
+-------------+---------+
product_id는 이 테이블의 기본 키(고유한 값을 가지는 열)입니다.
low_fats는 ('Y', 'N') 타입의 ENUM(범주)으로, 'Y'는 이 제품이 저지방임을 의미하고 'N'은 그렇지 않음을 의미합니다.
recyclable은 ('Y', 'N') 타입의 ENUM(범주)으로, 'Y'는 이 제품이 재활용 가능함을 의미하고 'N'은 그렇지 않음을 의미합니다.

 

저지방이면서 재활용 가능한 제품들의 id를 찾는 솔루션을 작성하세요.

결과 테이블은 어떤 순서로든 반환할 수 있습니다.

결과 형식은 다음 예시와 같습니다.

 

예제 1:

입력:
Products table:
+-------------+----------+------------+
| product_id  | low_fats | recyclable |
+-------------+----------+------------+
| 0           | Y        | N          |
| 1           | Y        | Y          |
| 2           | N        | Y          |
| 3           | Y        | Y          |
| 4           | N        | N          |
+-------------+----------+------------+
출력:
+-------------+
| product_id  |
+-------------+
| 1           |
| 3           |
+-------------+
설명: 제품 1과 3만 저지방이면서 재활용 가능합니다.

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: Products 테이블 전체에 대해 단일 테이블 스캔(product_id가 PK이므로 조건에 맞는 행은 WHERE 필터링만으로 처리) 1회 수행, 별도의 조인이나 서브쿼리 없음

### 잘한 점

- WHERE 절에 조건을 AND로 결합하여 불필요한 조인이나 서브쿼리 없이 단일 스캔으로 문제를 해결함
- PK 특성을 활용해 DISTINCT 없이도 중복 없는 결과를 보장함
- 요구사항에 맞게 ORDER BY를 생략하여 불필요한 정렬 비용을 피함

### 개선할 점

- SQL 키워드(SELECT, FROM, WHERE)의 대소문자가 일관되지 않아 가독성이 다소 떨어짐 (예: SELECT는 대문자, from/where는 소문자)
- 컬럼명과 테이블명 사이 들여쓰기나 줄바꿈 스타일을 통일하면 코드 스타일 일관성이 향상될 수 있음

### 상세 피드백

이 쿼리는 문제에서 요구하는 '저지방이면서 재활용 가능한 제품의 ID 조회'를 정확하고 간결하게 해결하고 있습니다. WHERE 절에 두 조건을 AND로 결합한 것은 가장 직관적이고 효율적인 방법이며, ENUM 타입 컬럼에 대해 문자열 비교를 그대로 사용한 것도 적절합니다. product_id가 기본키이므로 중복 제거를 위한 DISTINCT가 불필요한데, 이를 추가하지 않은 점도 좋습니다. 결과 순서는 문제에서 'any order'를 허용하므로 ORDER BY를 생략한 것도 올바른 선택입니다. low_fats와 recyclable 컬럼에 NULL 값이 들어갈 수 없는 ENUM('Y','N') 타입이므로 NULL 처리에 대한 추가 로직도 필요 없습니다. 전반적으로 불필요한 서브쿼리, 조인, 윈도우 함수 없이 단순 필터링만으로 문제를 해결했으며, 실행 계획 측면에서도 테이블을 한 번만 스캔하므로 성능상 개선할 부분이 거의 없습니다. 코드 가독성도 양호하나, 들여쓰기와 키워드 대소문자 통일(SELECT, FROM, WHERE 모두 대문자 또는 소문자로 일관되게)을 신경 쓰면 더 깔끔해질 것입니다.
