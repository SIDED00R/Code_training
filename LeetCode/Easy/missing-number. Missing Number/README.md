## 문제 설명

[0, n] 범위에서 n개의 서로 다른 숫자를 포함하는 배열 nums가 주어집니다. 배열에서 빠져 있는, 해당 범위의 유일한 숫자를 반환하세요.

 

예제 1:

입력: nums = [3,0,1]

출력: 2

설명:

숫자가 3개이므로 n = 3이고, 따라서 모든 숫자는 [0,3] 범위에 있습니다. 2는 nums에 나타나지 않으므로 해당 범위에서 빠진 숫자입니다.

예제 2:

입력: nums = [0,1]

출력: 2

설명:

숫자가 2개이므로 n = 2이고, 따라서 모든 숫자는 [0,2] 범위에 있습니다. 2는 nums에 나타나지 않으므로 해당 범위에서 빠진 숫자입니다.

예제 3:

입력: nums = [9,6,4,2,3,5,7,0,1]

출력: 8

설명:

숫자가 9개이므로 n = 9이고, 따라서 모든 숫자는 [0,9] 범위에 있습니다. 8은 nums에 나타나지 않으므로 해당 범위에서 빠진 숫자입니다.

 

 

 

 

 

제약 조건:

n == nums.length

1 <= n <= 10^4

0 <= nums[i] <= n

nums의 모든 숫자는 고유합니다.

 

심화 문제: O(1)의 추가 공간 복잡도와 O(n)의 실행 시간 복잡도만을 사용하는 solution을 구현할 수 있을까요?

## 코드 리뷰

- 효율성: 보통
- 시간복잡도: 시간복잡도 O(N log N) (정렬 비용), 공간복잡도 O(N) (sorted()가 새 리스트 생성)
- 더 나은 알고리즘: 가우스 합 공식을 이용해 O(N) 시간, O(1) 공간으로 풀 수 있습니다. expected_sum = n*(n+1)//2, actual_sum = sum(nums), 정답은 expected_sum - actual_sum. 혹은 follow-up 요구사항대로 XOR 비트 연산을 이용해도 O(N) 시간, O(1) 공간이 가능합니다 (missing = n; for i, num in enumerate(nums): missing ^= i ^ num). 두 방법 모두 정렬보다 빠르고 추가 공간을 거의 쓰지 않습니다.

### 잘한 점

- 변수명이 직관적이고 코드가 간결해 가독성이 좋음
- 반복문 끝까지 누락값을 못 찾았을 때 len(nums)를 반환하는 엣지케이스(배열 끝에 숫자가 빠진 경우)를 올바르게 처리함
- 정렬 후 인덱스 비교라는 아이디어 자체는 직관적이고 이해하기 쉬움

### 개선할 점

- O(N log N) 시간복잡도로, 문제의 follow-up이 요구하는 O(N) 시간 복잡도를 만족하지 못함
- sorted()로 인해 O(N)의 추가 공간이 사용되어 O(1) 공간 제약도 만족하지 못함
- 가우스 합 공식이나 XOR 연산 같은 더 간단하고 효율적인 수학적/비트 연산 풀이를 활용하지 못함

### 상세 피드백

이 풀이는 정렬 후 인덱스와 값을 비교하여 누락된 숫자를 찾는 방식으로, 논리적으로는 명확하고 정확하게 동작합니다. 하지만 시간복잡도가 O(N log N)으로, 문제의 follow-up에서 요구하는 O(N) 시간 + O(1) 공간 조건을 만족하지 못합니다. sorted()는 원본 리스트를 변경하지 않기 위해 새 리스트를 생성하므로 O(N)의 추가 공간도 사용합니다. 이 문제는 Math/Bit Manipulation 태그가 붙어 있듯이, 가우스 합 공식(0부터 n까지의 합 - 실제 배열의 합)이나 XOR 비트 연산을 이용하면 단 한 번의 순회로 O(N) 시간, O(1) 공간에 해결할 수 있습니다. 정렬 기반 풀이는 Easy 난이도 문제치고 다소 오버엔지니어링된 접근이며, 더 간단하고 효율적인 수학적 풀이를 놓친 점이 아쉽습니다. 코드 자체의 가독성은 좋고 엣지케이스(배열 끝까지 못 찾았을 때 len(nums) 반환)도 잘 처리했습니다.
