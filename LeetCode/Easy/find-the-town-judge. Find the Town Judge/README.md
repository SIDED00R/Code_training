## 문제 설명

어느 마을에 1부터 n까지 번호가 붙은 n명의 사람이 있습니다. 이 사람들 중 한 명이 비밀리에 마을 판사라는 소문이 있습니다.

마을 판사가 존재한다면 다음이 성립합니다:

마을 판사는 아무도 믿지 않습니다.

마을 판사를 제외한 모든 사람은 마을 판사를 믿습니다.

속성 1과 2를 만족하는 사람은 정확히 한 명입니다.

사람 ai가 사람 bi를 믿는다는 것을 나타내는 배열 trust[i] = [ai, bi]로 구성된 배열 trust가 주어집니다. 만약 trust 배열에 어떤 신뢰 관계가 존재하지 않는다면, 그러한 신뢰 관계는 존재하지 않는 것입니다.

마을 판사가 존재하고 식별할 수 있다면 마을 판사의 번호를 반환하고, 그렇지 않다면 -1을 반환하세요.

 

예제 1:

입력: n = 2, trust = [[1,2]]
출력: 2

예제 2:

입력: n = 3, trust = [[1,3],[2,3]]
출력: 3

예제 3:

입력: n = 3, trust = [[1,3],[2,3],[3,1]]
출력: -1

 

제약 조건:

1 <= n <= 1000

0 <= trust.length <= 10^4

trust[i].length == 2

trust의 모든 쌍은 고유합니다.

ai != bi

1 <= ai, bi <= n

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: O(N + T) 시간, O(N) 공간 (N = 사람 수, T = trust 배열 길이)

### 잘한 점

- in-degree/out-degree 카운팅이라는 이 문제의 최적 해법을 정확히 구현하여 O(N+T) 시간복잡도를 달성함
- 트러스트 관계를 한 번의 순회로 집계하고, 조건을 만족하는 사람이 두 명 이상이면 즉시 -1을 반환하는 등 '정확히 한 명' 조건을 올바르게 처리함

### 개선할 점

- in_count/out_count 두 개의 defaultdict를 쓰는 대신 하나의 score 배열(net = in - out)로 통합하면 코드가 더 간결하고 메모리 효율적임
- dic, point라는 변수명이 역할을 명확히 드러내지 못해 가독성이 떨어지며, n=1 특수 처리 로직이 임시방편적이어서 1..n 순회 방식으로 바꾸면 더 일관된 코드가 됨

### 상세 피드백

이 풀이는 Find the Town Judge 문제의 표준적이고 최적인 접근 방식인 in-degree/out-degree 카운팅을 정확히 구현했습니다. 신뢰를 받는 횟수(dic)와 신뢰를 하는 횟수(point)를 각각 집계한 뒤, 신뢰를 n-1번 받고 아무도 신뢰하지 않는 사람을 찾는 로직이 문제의 조건을 그대로 반영하고 있어 정답성과 시간복잡도 모두 우수합니다. O(N+T)로 선형 시간에 해결하므로 이 문제에서 더 빠른 알고리즘은 존재하지 않습니다.

다만 세부적으로 개선할 점이 있습니다. 첫째, in-degree와 out-degree를 각각 별도의 defaultdict로 관리하는 대신, score[b] += 1; score[a] -= 1 형태로 하나의 배열에 통합하면 코드가 더 간결해지고 메모리도 절반으로 줄어듭니다 (판사라면 score가 n-1이 됨). 둘째, n=1 예외 처리가 다소 임시방편처럼 느껴지는데, 이는 trust가 비어 있을 때 dic이 비어서 루프가 돌지 않아 -1이 반환되는 버그를 막기 위한 것으로 보입니다. 이 경우 1부터 n까지 순회하며 조건을 확인하는 방식으로 바꾸면 n=1 특수 처리가 필요 없어집니다. 셋째, 변수명 dic, point가 의미를 명확히 전달하지 못하므로 in_count, out_count 같은 이름이 가독성에 더 좋습니다. 넷째, defaultdict(int)를 사용했지만 실제로 int 기본값 0을 활용하는 부분이 point[a]를 조회할 때뿐이라 Counter를 써도 무방합니다. 전반적으로 정답이며 효율적이지만, 코드 스타일과 엣지케이스 처리 방식에서 약간의 다듬을 부분이 있습니다.
