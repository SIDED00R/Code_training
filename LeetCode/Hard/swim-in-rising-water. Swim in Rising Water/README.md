## 문제 설명

각 값 grid[i][j]가 지점 (i, j)의 고도를 나타내는 n x n 정수 행렬 grid가 주어집니다.

비가 내리기 시작하고 시간이 지남에 따라 물이 점점 차오릅니다. 시간 t일 때, 수위는 t이며, 이는 고도가 t 이하인 모든 칸이 물에 잠기거나 도달 가능하다는 것을 의미합니다.

어떤 칸에서 4방향으로 인접한 다른 칸으로 수영해 갈 수 있는 것은, 오직 두 칸의 고도가 각각 t 이하일 때입니다. 무한한 거리를 시간 소요 없이 수영할 수 있습니다. 물론 수영하는 동안 그리드의 경계 내에 있어야 합니다.

왼쪽 상단 칸 (0, 0)에서 시작하여 오른쪽 하단 칸 (n - 1, n - 1)에 도달할 수 있는 최소 시간을 반환하세요.

 

예제 1:

입력: grid = [[0,2],[1,3]]
출력: 3
설명:
시간 0에서 당신은 그리드 위치 (0, 0)에 있습니다.
t = 0일 때 4방향으로 인접한 칸들의 고도가 모두 더 높기 때문에 다른 곳으로 갈 수 없습니다.
시간 3이 될 때까지는 지점 (1, 1)에 도달할 수 없습니다.
물의 깊이가 3일 때, 그리드 내 어디로든 수영할 수 있습니다.

예제 2:

입력: grid = [[0,1,2,3,4],[24,23,22,21,5],[12,13,14,15,16],[11,17,18,19,20],[10,9,8,7,6]]
출력: 16
설명: 최종 경로가 그림에 나타나 있습니다.
(0, 0)과 (4, 4)가 연결되려면 시간 16까지 기다려야 합니다.

 

제약 조건:

n == grid.length

n == grid[i].length

1 <= n <= 50

0 <= grid[i][j] < n^2

각 값 grid[i][j]는 고유합니다.

## 코드 리뷰

- 효율성: 효율적
- 시간복잡도: 시간복잡도 O(N^2 log N), 공간복잡도 O(N^2) (N = grid의 한 변 길이, 전체 노드 수는 N^2)

### 잘한 점

- min-max path 문제의 핵심을 정확히 파악하여 Dijkstra/Prim 스타일 heap 탐색으로 효율적으로 구현함
- push 시점에 visited 마킹을 하여 중복 push를 방지하고, 이것이 단조성(w가 감소하지 않음)에 의해 정확성을 보장받는 점을 잘 활용함
- n=1 같은 엣지케이스도 별도 분기 없이 자연스럽게 처리됨
- 방향 배열(di, dj)을 이용한 깔끔한 4방향 탐색 구조

### 개선할 점

- 10000이라는 매직 넘버를 사용해 '무한대'를 표현하고 있어 가독성이 떨어지고, grid 값 범위가 바뀌면 버그로 이어질 수 있음 (float('inf') 권장)
- 목적지 (n-1, n-1)에 도달한 후에도 heap 탐색을 계속 진행하는데, 조기 종료(early return) 로직이 없어 불필요한 연산이 약간 발생함 (성능에 큰 영향은 없지만 가독성 측면에서 개선 가능)
- 변수명 weight가 실제로는 '도달 가능 시간(최소 t)'을 의미하는데 이름이 의미를 직관적으로 전달하지 못함
- heap에 리스트([w, i, j])를 사용하고 있는데, 불변 데이터이므로 튜플을 사용하는 것이 Python 관례에 더 맞고 약간의 성능 이점도 있음

### 상세 피드백

이 코드는 '최소-최대 경로(minimax path)' 문제를 Dijkstra/Prim 변형 방식으로 정확하게 풀고 있습니다. 핵심 아이디어는 heap에서 꺼내는 가중치(w)가 단조 비감소(non-decreasing)한다는 성질을 이용해, 노드를 '처음 발견하는 순간'의 비용이 바로 그 노드에 도달하는 최소 비용임을 보장하는 것입니다. 이는 표준 Dijkstra처럼 pop 시점에 확정하는 대신 push 시점에 visited 마킹을 하는 lazy-free 변형인데, 각 edge weight가 max(grid[a], grid[b], 현재값)으로 단조 증가하기 때문에 정확성이 유지됩니다. 전체 노드 수가 N^2, 각 노드당 최대 4개 edge를 고려하면 heap 연산이 최대 O(N^2)회 발생하고 각 연산이 O(log N) (heap 크기가 N^2이므로 log(N^2)=2logN)이므로 총 O(N^2 log N)으로, Binary Search+BFS/DFS, Union-Find 방식과 동일한 최적 복잡도 수준입니다. N<=50 제약에서 충분히 빠르게 동작합니다. 다만 매직 넘버 10000(이는 n^2 최대값 2500보다 커야 함을 암묵적으로 가정한 것)을 float('inf')로 바꾸면 의도가 더 명확해지고, 목적지 (n-1,n-1)에 도달하는 즉시 반환하는 조건을 추가하면 약간의 성능 개선과 가독성 향상을 동시에 얻을 수 있습니다. 또한 변수명 weight는 '도달 시간(최소 t)'을 의미하므로 dist나 min_time 등으로 바꾸는 것이 의미 전달에 더 적합합니다.
